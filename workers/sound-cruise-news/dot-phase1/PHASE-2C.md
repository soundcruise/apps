# Phase 2C — isolated matching and persistence boundary

This is a local prototype, not imported into either Worker. `identity-2c.mjs` accepts aliases and event attestations in a separate trusted argument, never from candidate JSON. A production adapter must implement and authenticate that trust boundary; the module itself does not establish that an attestation or alias is true. It never creates formal facts, READY, scope overrides, publication decisions, or DB writes.

Kim Gordon fixture: the stored Ikebe article and the Dot report describe matching names, but the Dot report is not a signed independently reviewed primary-evidence record. A **simulated** approved alias pair and simulated attestation demonstrate the new comparison; without those extra inputs Kim remains UNCERTAIN. This must not be reported as a production-confirmed automatic SAME. The source-based allowance and 90-day rules remain separate. NEURIG event remains `source_event_scope`; a simulated verified event difference does not turn it into an eligible candidate. Individual rejections and system exclusions remain separate; the actual MOTU actor type is not established here, so the fixture records it as unconfirmed.

14-item before/after: the Phase 2B review was 0 SAME / 1 DISTINCT / 13 UNCERTAIN. With a simulated independently approved Kim alias and event attestation the fixture comparison changes N02 to SAME: 1 / 1 / 12. Without those simulated inputs the supported production-evidence baseline remains 0 / 1 / 13. This is a conditional test, not a measured production improvement; no archived history snapshot or publisher evidence is reconstructed.

Future persistent design (not implemented): policy-versioned proof ledger, normalized identity aliases with source scope and reviewer, event relations and tombstone/retention reasons, producer request key + canonical payload digest under one atomic unique transaction, a typed receipt for ACK-loss replay, revision fence and approval separation, bounded retention compatible with takedown/deletion. A same key plus different digest must conflict; concurrent retries must have one effect; unavailable/deleted history yields unknown, never no duplicate. Privacy and deletion obligations govern retention. DOT submissions never create trusted attestations.

Test via `node --test engine.test.mjs phase2c.test.mjs`. The original Phase 1 `compareEvents` remains for backward compatibility. No production candidate importer uses either matching prototype.

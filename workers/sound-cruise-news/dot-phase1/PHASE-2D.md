# Phase 2D — independently bound evidence prototype

The adapter is offline-only and is not imported by any Worker. Its `repo`, `policies`, and parser allowlist are controlled inputs from a separate trusted boundary, never supplied by a Dot candidate. This boundary is NOT yet authenticated or implemented for production. Supplying a fabricated repository or trusting a parser merely because it says it is trusted would defeat the prototype. SHA-256 of the structured record detects inconsistency relative to its supplied digest; it is not a signature, proof of publisher authorship, or a replacement for trusted storage and source access controls.

The adapter checks policy revision, allowed acquisition method and scope, URL/candidate binding, exact fields, source/parser allowlist, record digest and recorded response hash; it rejects conflicting input claims. It generates Phase 2C aliases and event attestation only from separately provided parser records with explicit canonical IDs and event IDs. A differing ID alone does not establish a different event. Product announcement and an independently established event announcement can be separated, with scope and decision status preserved. The adapter never writes or fetches, and never makes formal facts, READY, approval or publication.

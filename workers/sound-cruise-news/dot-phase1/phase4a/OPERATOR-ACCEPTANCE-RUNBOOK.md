## Short, separately approved acceptance

1. Integrate the reviewed, tested tree into main only if separately approved, with head checks, conflict review, no unintended NEWS collector/cron/binding change, and Pages safeguards. Deploy only the Operator Worker with Dot OFF if separately approved. Check deployment ID, `/api/session`, existing review functions, bindings and authenticated `/api/dot-capabilities`; on errors stop and roll back.
2. Under separate approval, create a Cloud Run revision using the *single* existing Operator Access audience, same issuer, allowlisted human, reader identity and image. Do not include the isolated audience; verify the mismatched token is rejected in local tests. Keep Invoker IAM enabled during revision preparation. Preserve previous Cloud Run revision and traffic mapping; verify same region, Firestore, min 0/max 1, concurrency 4, timeout 10 seconds.
3. Configure only Operator Dot origin and enable flag through secret/binding management, without changing existing Access, D1, pepper, human allowlist or other secrets. Confirm OFF first, then ON only inside monitored window. The safe default is OFF.
4. Because Worker-to-Google IAM identity has not been proven, the prior isolated experiment used temporary unauthenticated Cloud Run ingress plus independently verified Access JWT. If and only if explicitly approved for this short test, disable the Cloud Run Invoker IAM check temporarily. This exposes an HTTP entry before application authentication: monitor request count, 5xx, duration and cost. Use a watchdog with a 120-second maximum and stop at more than 30 requests, more than 5 server errors, unexpected access, missing monitoring, auth/read failure or cost anomaly. Verify missing and invalid JWT return 401, then use normal browser Access login to view the fictional candidate. Never copy JWTs/cookies into shell, logs, files or tickets.
5. In all success/failure/timeout paths, first restore Cloud Run Invoker IAM; verify an unauthenticated request returns 403. Turn Operator Dot OFF and verify authenticated capabilities reports unavailable. Restore the previous Cloud Run revision/traffic and isolated audience; verify identity, image and readiness. Verify the production Operator's existing functionality. If restoration fails, stop all other work and restore the boundary before proceeding.
6. If the Worker deployment itself is faulty, use the preflight-recorded Wrangler version ID with the documented `wrangler rollback` flow; verify the version, auth and health. A rollback of code does not roll back D1, secrets or Cloud Run. No D1 write or migration belongs to this plan.

## Remaining conditions

Short acceptance does not establish unattended, always-on deployment. The preferred steady state keeps Invoker IAM and requires a verifiable Google-signed service ID token for a least-privileged caller, without a long-lived key. The Cloudflare Worker external workload identity for that route remains unproven. A public Cloud Run entry protected only by application JWT cannot be treated as a distributed rate limit or hard billing cap; stronger ingress/abuse protections and their costs require separate evaluation and approval.

NEWS comparison is a targeted reference search, not formal SAME or DISTINCT. Each retained scope has a bounded match limit, and short model names, aliases, orphan records and expired history can be missed. Results must remain UNCERTAIN and must not revive rejects or takedowns.

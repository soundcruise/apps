# Isolated Dot review UI

The isolated Worker serves a read-only shell and the same Dot review renderer used by Operator. Every shell, asset and candidate request passes existing Access authentication and human authorization; no D1 binding, mutation, or decision endpoint is present. The relay remains off by default. Values are rendered as text and links accept only HTTPS without credentials.

The NEWS comparison adapter accepts a bounded snapshot supplied through an authorized server-side reader. The Operator code can read its existing D1 binding; this change is not deployed to production. It records coverage for approved, pending, rejected, system exclusions, discovery, decision ledger and takedowns; missing or failed sources are unexamined. Similarities are only navigation aids and the result remains UNCERTAIN with incomplete history. It cannot alter past decisions or treat a missing match as a formal non-duplicate.

Local preview supports a signed fixture (`createLocalOperator(reader, {isolated:true})`); it is not evidence of real Cloudflare Access. Real Cloud Run and Firestore data were not modified by this change. A real screen test needs separate authorization for deployment of the isolated Worker and for a supervised, time-limited Cloud Run ingress trial, followed by restoring Invoker IAM and disabling the relay. No production Operator deployment is included.

When the Operator has an existing NEWS D1 binding and Dot review is enabled, an authenticated candidate-detail request now uses a bounded SELECT-only reader for each retained scope. It searches by candidate ID, verified-format source URLs and model/product strings of at least four characters, using bound parameters. It reads matches in pages of 100, up to 500 per scope; it does not repeatedly export each full table. Alias variants, short models, orphaned history, failed queries and truncation can leave matches undiscovered; the scope therefore denotes a targeted search, not a complete duplicate check. Failures and truncation are disclosed. Reads are separate, not a transactional snapshot, and expired history cannot be recovered. The UI reports scope coverage and retained-history limitations. Isolated Worker deliberately has no D1 reader. The existing formal duplicate predicate requires a verified NEWS candidate, so unverified Dot candidate claims are never converted into formal SAME/DISTINCT. Formal comparison remains NOT_EVALUATED and the overall result UNCERTAIN. Integrating a verified identity/provenance path and proving current production coverage remain separate work.

# Phase 4B Operator confirmation: incomplete / disabled

`NEWS_DOT_CONFIRMATION_ENABLED` is absent by default and must remain off until a separately approved deployment, migration and acceptance. When enabled, the Operator authenticates and authorizes the Access human, requires the existing CSRF and Origin checks, and records that person's bounded observations separately from Dot claims. The display asks for source, identity, event, date, claims, usage policy and NEWS history. A human's entry of “confirmed” is an observation, not independently established permission, official NEWS facts, a duplicate decision or publication approval.

The Firestore adapter exposes the document update time (seconds and nanoseconds) as the staging revision. The Operator hashes the canonical projected candidate and re-reads the upstream record before saving. Missing or changed revisions and changed candidate content are rejected. Because the read and D1 write are not one transaction, a Firestore change after the re-read can still race the insert. Any later consumer MUST re-read and compare both the candidate digest and revision immediately before use; this release has no such consumer and cannot register candidates.

Migration 0025 adds only the confirmation table and candidate index. Each confirmation request ID is unique; an identical request by the same actor replays and a different body conflicts. A single SQL insertion is atomic, but this is not the D1 registration transaction and does not prove two-system atomicity or a production D1 durability property. File-backed SQLite tests are local evidence only.

No generic source authorization, formal-facts promotion, complete historical duplicate check, durable D1 admission/receipt, or Operator registration action is implemented. Existing Yamaha assisted permissions are not extended. The source observations are not fed to `saveAssisted`. There is no publish, approve, reject or admission button in this change. Real Access, Firestore update-time behavior, the deployed UI, and D1 have not been tested with this change. Phase 4B remains HOLD.

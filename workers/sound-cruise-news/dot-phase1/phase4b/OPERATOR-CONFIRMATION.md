# Phase 4B Operator confirmation and admission: limited / disabled

`NEWS_DOT_CONFIRMATION_ENABLED` and `NEWS_DOT_ADMISSION_ENABLED` are absent by default and remain off until separately approved migration, deployment and acceptance. The Operator authenticates and authorizes the Access human and requires the existing CSRF and Origin checks. Human observations, candidate digest, Firestore revision, actor and time are retained separately from Dot claims. A human entry is not in itself third-party permission or publication approval.

The existing Yamaha manually verified guitar Topics path is unchanged. Generic official-source admission additionally requires a server-side reviewed `manualFactsPolicy`: a matching official manufacturer and exact source/path, approved and current permission reference and evidence URL, human-only acquisition, independent facts only, and no quotation, reproduction or images. Existing NEWS source, health, identity, facts and duplicate gates still apply. No real generic source policy has been added by this change: the positive non-Yamaha example uses a synthetic registry entry only. Retailer and media sources are held until primary-source binding and source-specific permissions have been implemented and verified. Merely providing a URL or claiming permission does not enable a source.

Each bound observation includes a value and human-provided locator; unknown expired history requires a separate acknowledgement. Formal duplicate matches, reference similarity and incomplete history remain distinct. Exact URL / candidate-ID history and duplicate fences are rechecked in the D1 batch, but cross-source aliases and expired or orphan histories cannot be completely reconstructed. A no-match is not proof of global uniqueness.

The Firestore document update time is the staging revision. The Operator hashes the projected candidate and re-reads digest, revision and delivery key hash immediately before D1 admission. Firestore and D1 are separate systems: an update after that read can still race the D1 commit. Receipt is authoritative in D1; no Firestore write is performed. The receipt read endpoint reports MATCH, CHANGED or UNCERTAIN by comparing the current staging snapshot, but existing NEWS approval does not automatically enforce this cross-system check; the feature must remain off until that safety gap is resolved.

Migration 0025 creates human confirmations; 0026 creates a unique admission receipt and batch postcondition guard. The D1 batch inserts the NEWS candidate, assisted audit and receipt together. Replays inspect the committed receipt and current candidate status; conflicting requests fail. Local tests use independent SQLite processes for restart and concurrent admission. A synthetic Operator fixture was also run on Wrangler local D1 binding: Yamaha and an independently permitted fictional official source entered the existing pending queue; browser confirmation, receipt lookup after a server restart, replay and injected receipt rollback succeeded. Local workerd required compatibility date 2026-09-18 rather than the repository's 2026-10-02 and this difference remains a limitation.

Generic non-Yamaha admissions are marked as requiring the publication gate in the Operator; direct approval is also blocked until source-policy and Firestore freshness can be enforced through publication. Rejection remains available. No auto-approval or publication is added. Generic real-world source permissions, third-party primary-source binding, actual Cloudflare Access, Firestore and deployed D1 E2E are not established. Phase 4B remains HOLD.

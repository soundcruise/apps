# Phase 4B Operator confirmation and admission: limited / disabled

The feature flags `NEWS_DOT_CONFIRMATION_ENABLED` and `NEWS_DOT_ADMISSION_ENABLED` are absent by default and must remain off until separately approved migration, deployment and acceptance. The Operator authenticates and authorizes the Access human and requires the existing CSRF and Origin checks. Observations, candidate digest, Firestore revision, actor and time are retained separately from Dot claims. A human's entry of “confirmed” is not itself third-party permission or publication approval.

The only admission path currently implemented is the existing Yamaha manually verified guitar Topics permission, without publisher fetching or reproduction. Each bound observation must include a value and a human-provided evidence locator, and a separate explicit acknowledgement is required for unavailable expired history. Other sources are held. The server checks candidate source, identity, event and known date against those observations, reuses existing assisted validation and duplicate logic, and holds on any bounded history match or incomplete search. Exact URL / candidate-ID history and duplicate fences are rechecked inside the D1 batch. Cross-source identity and expired or orphan histories cannot be completely reconstructed; a no-match is not proof of global uniqueness.

The Firestore document update time is the staging revision. The Operator hashes the projected candidate and re-reads digest, revision and delivery key hash immediately before D1 admission. Firestore and D1 are separate systems: an update after that read can still race the D1 commit. This is not cross-database atomicity. Receipt is authoritative in D1; no Firestore write is performed.

Migration 0025 creates human confirmation records. Migration 0026 adds a receipt with unique request, candidate, delivery and confirmation IDs plus a batch postcondition table. The D1 batch inserts the existing NEWS candidate, assisted audit and Dot receipt together; a failing insert or postcondition rolls back the batch. Replays inspect the committed receipt and current candidate status; conflicting requests fail. Local tests exercise file-backed SQLite, independent processes, lost ACK, concurrent admission and rollback. Local Wrangler D1 migration was applied, but actual D1 admission behavior and real Access / Firestore / browser E2E remain unverified.

No generic source authorization, automatic approval, publication or complete duplicate-history guarantee is added. The admission UI is not a publication decision. Deployments must not enable this while the above limitations and unsupported sources remain unaccepted. Phase 4B remains HOLD pending actual cloud acceptance and the generic source-policy work.

# Dot publication gate: isolated acceptance and limits

The Operator feature `NEWS_DOT_PUBLICATION_ENABLED` defaults off. When enabled, a Dot candidate can pass only with its admission receipt, unchanged staged digest/revision/delivery identity, valid original human confirmation, formal NEWS validation and policy, a fresh human source observation and candidate-specific history attestation, and no disqualifying or unscoped orphan history. The source and history attestations expire after five minutes and are bound to the exact D1 row snapshot and receipt. Short model identifiers or incomplete scans HOLD. A known SAME, exact retained exclusion, target/source takedown or policy rejection BLOCK. PASS is permission for a separate authenticated human decision, not automatic publication.

The history attestation records the operator's stated scope, basis, archive reference, actor and time. It is not an automated verification that an archive is complete: an operator must actually verify deleted/expired history and aliases using an independent record. Unknown orphan history cannot be waived. The original source is not fetched by this route; the operator must manually review it under source-specific allowed terms and attest independent text/no reproduction. The server does not infer permissions from the attestation.

A bounded snapshot of 13 D1 safety tables is compared inside the same conditional decision INSERT as the row CAS, duplicate predicate, source stop and takedown checks. The decision and audit are committed by the existing ledger trigger. This version HOLDs if the snapshot exceeds 500 total rows or 262144 bytes; it scans and orders the tables on each check and is unsuitable for large production data until a scalable candidate-scoped fence is demonstrated. No triggers are added to ordinary NEWS writes. A change reverted to identical D1 state is not detectable. The external Firestore document and publisher can change after the final read and are not locked by D1. A five-minute attestation and late reread reduce, but do not eliminate, that race.

No new real source is enabled. Existing Morris permission in NEWS-SOURCE-DECISION-REGISTER.md applies only to its existing narrow policy and is not general permission for this workflow. Non-Yamaha success is tested only with an explicitly allowed fictional policy; real publishers require independent source-specific evidence. Direct publisher fetching and reproduction rights are unchanged.

Migration 0028 adds the history attestation table only. Applying migrations, deploying the Worker or enabling the feature requires separate authorization and a recovery plan. Disabling the flag blocks new Dot approvals; rolling back code does not reverse an already committed decision or remove migration data. Live Access, Firestore and D1 acceptance, evidence-backed history procedures, scale tests, external race mitigation, and the impact of pre-existing orphan records remain unverified.

The snapshot preflight batches schema discovery and size/count checks before retrieving any serialized rows; the exact final comparison is still unchanged and fail-closed. This reduces snapshot construction from 26 D1 statements to three, but does not raise the 500-row/256 KiB limits, remove global orphan/unknown-identity holds, or make production-scale approval possible. The preflight and exact snapshot are separate reads; concurrent data growth can still cause a larger exact result before its size check. No operator should enable the feature based only on this optimization. A bounded candidate-scoped fence needs to preserve the existing formal duplicate predicate (including legacy identity and provenance), detect newly relevant rows and unscoped history inside the final D1 decision, and demonstrate actual D1 limits before this can be removed.

A retained human rejection with an exact recorded article URL hash now blocks Dot registration and publication even if its candidate row is missing. Hash nonmatches do not prove unrelatedness; the global orphan/unknown-identity holds and the full-state fence remain in force. The registration INSERT repeats the rejection-hash condition within the atomic D1 batch; no automatic NEWS collection path is changed.

Candidate-centred exact URL hashes now detect retained human rejection even when the original candidate row is absent, and an atomic admission condition prevents a matching rejection that arrives during registration. A hash mismatch does not prove unrelatedness or recover expired history. The candidate-centred search explicitly reports incomplete when source/model/URL terms are truncated; admission and publication remain HOLD. The existing global fence is unchanged and still cannot pass production-sized or unresolved-orphan state. A candidate-scoped replacement requires exact coverage of identity changes and orphan-specific, independently evidenced determinations, and must remain fenced in the final D1 statement.

The candidate-centred search treats more than eight source entries, more than eight unique source URLs or models, and malformed URLs as incomplete instead of silently truncating a search. The current full-state fence still applies unchanged. Retained URL hashes cover exact article identity only; differently addressed reports of the same event and records with no hash still require independent candidate-specific evidence. The present history attestation does not record a separately verified decision for each orphan, so it must not be used to waive the global orphan hold.

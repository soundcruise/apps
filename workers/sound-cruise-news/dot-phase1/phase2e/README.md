# Phase 2E — local fixture review, not production

Run from `dot-phase1` after `npm ci`: `node phase2e/server.mjs`. It binds only 127.0.0.1, creates a fresh temporary `dot2e-*` SQLite DB, loads the 14-report fixture and prints its local URL. Stop with Ctrl-C; the demo DB is deleted on normal shutdown. Starting the server again deliberately creates a new demo DB. `store.mjs` also supports reopening the same isolated temp DB: its persistence / concurrent process / lost-ACK tests use that path, not a production database.

`node phase2e/import.mjs <isolated staging.sqlite> <candidate JSON>` accepts one Phase 1 object or up to 50 objects. Only a `staging.sqlite` inside a real temporary `dot2e-*` directory can be opened. Schema validation runs before transaction; source self-report is not trusted. A receipt keyed by request ID and canonicalized payload hash is committed atomically with the candidate using `BEGIN IMMEDIATE`. Same key and equivalent data replay; different data conflict. This has no cross-system acknowledgement protocol and has not been tested on D1 or other real deployments.

The existing-news subset is derived from the previous read-only audit plus labelled synthetic decision examples. It is not the live 229-record production snapshot and cannot establish all-history uniqueness. Similarity is a navigation hint and never a formal SAME, editorial approval, permission or proof. Dot's original structured input and computed validation are in separate columns; canonicalization preserves the data values, not original JSON bytes. All policies remain unconfirmed. The isolated demo verdicts are synthetic and stored in a separate SQLite table, not publication decisions or teacher data. Incomplete history and source scope are shown.

No external HTTP is made by this application, except if a person deliberately follows an article link in their browser. The local HTTP interface has exact loopback host, origin and per-run CSRF token checks; it is not an authenticated production service. Its default CSP and textContent rendering prevent HTML execution in the demo. Do not expose it publicly or point it at production. `node:sqlite` is experimental in the present Node 24 runtime; no production readiness is claimed.

# 記事案の入力補助と掲載判断（0.60.0）

保存済みWebヒントのAI案は変更せず、既存の人間確認フォームへ読み込みます。
公開日メタデータは「公開日候補・未確認」として使い、更新日時からは作りません。
正式候補・機械取得証拠・人間確認済みのfactsを、この読み込みで作成しません。

## 提供された確認用情報を一度だけ準備する

記事ごとのコード追加は不要です。既存ヒントURLに結び付いた小さなJSONをローカルで用意します。
`version: 1`、`url`、`source: {label, url}`、`fields`、任意の`notes`を指定します。
`fields`はbrand/product/productType/action/publishedAt/label/eventDate/venueのみです。
原記事の本文、画像、秘密情報、確認チェック、掲載許可、provenanceは入れません。
`notes`のlabel/valueは参考表示のみで、正式factsには保存しません。

```sh
node scripts/assisted-draft-link.mjs information.json https://operator.example
```

出力リンクを開くと、既存の保存AI案と確認用情報を組み合わせて各欄へ入力します。
確認用情報はURLのフラグメントで渡し、検査後は同じタブの既存sessionStorageへURL別に保持します。
同じタブでWeb一覧から開き直した場合にも再利用します。DBに新しい記事案の表は作りません。
リンクは認証の代わりにはならず、機密情報を含めないでください。
読取用の`POST /api/assisted-draft`も既存Access・CSRF・入力サイズ制限を通します。
ヒントが存在しない・期限切れ・人間確認のURL範囲外の場合は読み込みを拒否します。

## 運営者の操作

1. 保存済みAI案／確認用リンクを開く。原記事を人間が通常閲覧する。
2. 入力済みの値を確認し、誤りや不足がある項目だけ訂正する。
3. 「掲載する」を押す。
4. 見出し・出典・日付と確認事項を読み、最終ダイアログの「確認して掲載」で確定する。

必要な情報が揃う記事案では、読了後は2クリック・最終確認1回です。
不足項目がある場合だけ「内容を修正」を開き、既存の値を保ったまま補完します。
「掲載しない」は同じ最終確認から既存Ledgerへ記録し、「あとで確認」は判断を保存しません。
確認チェックは初期状態で未選択です。最終ボタンの明示的な操作が、原記事の事実・日付・紹介条件・有用性・重複・独自見出しの確認意思になります。
入力補助や最終ダイアログを開く操作だけでは、候補・判断・公開を保存しません。
従来のチェック・プレビュー・候補保存は「個別の保存・編集（詳細）」に残します。
見出しは既存assistedLabelで生成し、訂正後は古い自動見出しを残さず再生成します。
元のAI案・入力元は閉じた詳細に残し、人間の最終確認と区別します。
確認用リンクや同じタブで開き直せば初期案を再読込できますが、画面上の訂正は正式保存まで未保存です。
タブの保持が使えない環境でも、確認用リンクから再読込できます。チェックは保持しません。

## 既存処理との境界

出典許可、URL範囲、publicationValidation、重複、takedown、CAS、Ledger、監査は変更しません。
保存時は従来どおり人間確認の証拠を記録し、AI推定や参考情報を機械取得の証拠へ格上げしません。
通常collector・cron・自動掲載条件は変更せず、追加の取得・推論も行いません。
本番へ適用するにはこの変更の統合・配備承認が必要です。migrationは不要です。

## 保存と判断の途中で失敗した場合

`POST /api/assisted-decision`は既存の`saveAssisted`→正式検証→`operatorDecision`を順に実行します。
それぞれの既存トランザクションを使い、複数の呼出全体を単一トランザクションとは扱いません。
事実保存後に判断が失敗した場合は、監査済みの未判断候補が残ります。「掲載済み」とは表示しません。
既存の「前回の判断結果を確認・再送」で同じrequest IDと内容を再送するか、保存済み候補を開きます。
再送は元の確認済み内容・actor・監査記録と照合し、既存Ledgerの冪等性を利用します。自動再試行はありません。
別の人間判断が先に確定していた場合は上書きしません。既に登録済みのURLは既存候補を表示し、判断済みなら新規操作を出しません。
同一タブの未完了送信記録には確認した入力を保持します。これは継続用の記録であり、新しい記事の確認チェックの初期値には使いません。

## 対象範囲

正式READYの通常bot候補も同じ最終確認を使い、既存`/api/decision`へ送ります。
factsが不足する既存候補の承認は従来どおり禁止し、非掲載判断は既存の理由選択で利用できます。
未登録のWeb記事では、出典範囲と人間確認factsを満たす既存の保存契約が先に必要です。情報不足を埋めたり、URLだけで非掲載候補を新設したりしません。
人間補完専用フォームや公開記事の訂正は従来の別操作を維持します。自動掲載の条件・学習教師の扱いは変更しません。

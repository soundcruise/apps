# 保存済みAI案 → 人間確認 → 既存NEWS（0.56.0候補）

基準main: 617ee9fcefa4bbf145b32349a772c12002ec52e5。PR255の既存UI・人間確認経路を拡張。新規DB、migration、掲載エンジン、クローラーなし。

## 再利用するもの

Gemmaの保存済み9項目estimate_jsonを記事案の原データとする。保存済み案から表示時にブランド・対象・出来事を組み合わせた短い日本語の独自見出し案を生成する。元記事の見出しのコピーではない。推定がない場合に記事案を捏造しない。機械的な投影であり、新たなAI生成・品質実証ではない。

既存ヒントAPIと既存GET /api/assisted?hintUrl=...で再読取する。URLパラメータは照合キーだけ。保存済みestimate以外からfactsを注入できず、日付ヒント・更新日時は入力しない。追加の推論も二重保存もない。

## 共通フロー

1. WebカードにAI見出し案、出典host、URL、状態、足りない項目を表示。AI推定・検索見出し・メタデータは既存詳細へ。
2. 許可済みTopicsのみ「AI案を確認」。保存案の主体・対象・出来事・種別を入力補助に使う。曖昧な種別は未選択。限定色・復刻等を通常発売へ読み替えず出来事を未確定にする。
3. 人間は原記事を通常閲覧し、入力済み項目を検証。不足する日付・種別などだけ補完し、誤りがあれば修正。記事本文や見出しを一から書くことは不要。原文の確認・利用条件のチェックは自動選択しない。
4. 既存preview/saveで人間確認証拠を保存。正式facts/provenance・重複・takedown等を既存publicationValidationで検証する。検索推定が正式証拠に変化するのではなく、運営者の確認入力が既存監査契約に保存される。
5. READY候補を既存審査一覧で掲載／非掲載判断。operatorDecision/Ledger/CAS/公開APIを再利用。保留は未判断のまま保持。「あとで確認」は保存済みAI案を残して一覧へ戻り、未保存の修正入力は保持しない。
6. すでに人間確認候補があるTopicsは、Bot取得のOFFと区別して既存候補を参照。正式検証は省略せず、既判断は再登録・再承認しない。

## 出典境界

A: 正式候補／機械証拠が成立すれば既存候補・検証へ。B: 許可済みcollector証拠がないURLを直接取得・候補登録しない。C: AI案は表示できても、利用条件がない出典の登録ボタンは出ない。

Yamaha Topicsの既存URL・許可範囲は変更なし。出典名は「ヤマハ / ヤマハミュージックジャパン」。直接Bot取得を追加しない。外部検索の問い合わせ回答は未確認のまま。一般ニュースリリースAcompass60はAI案表示まで、登録・掲載不可。許可が後日成立した場合は記事ID例外でなく既存出典契約を別承認で拡張する。

人間確認記事は機械取得済み証拠にしない。automatic.jsのpublisher_structured等の厳格条件、Shadowの教師選別、通常collector、正式publicationValidation、池部優先は変更なし。自動掲載・探索は本番OFFのまま。

## 受入と限界

保存estimate → draft再表示 → 人間が公開日を補完 → 既存save → READY → operatorDecision → Ledger1件／公開API1件のローカルE2E。重複保存は候補1件。別途fixture AccessのGETで再読取・未認証拒否・日付ヒントを不採用にすることを検証。

隔離されたlocalhostの実画面でも、AI入力済みの案に公開日だけを補って確認・保存し、既存掲載判断を完了。PC/390px幅、初期未チェック、未確認日付空欄を確認。使用した製品・Topics URL・確認主体は合成fixtureであり、実記事や本番掲載の証明ではない。外部HTTPは禁止したテスト環境のみ。

本番配備・統合・有料AI/検索・本番データ変更なし。実モデル品質は前回の保存結果以上には実証しない。本番導入はOFF配備・実Access読取を別承認。次に実在する許可済み記事で人間確認・掲載を受け入れる。定期探索は正式採用できる出典と費用・実モデル設定の確認後に別承認。自動掲載は前向き評価の蓄積と明示承認後。

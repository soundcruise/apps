# 11月13日 Web Cron未開始：原因と限定修正

## 本番証拠

2026-11-15、通常の既存Cloudflareアカウントでダッシュボードの保存済み
Observabilityイベントを読み取り、11月13日08:25〜08:50 JSTの3イベントを取得した。
Wrangler OAuthによる履歴ログAPIは403だったが、既存のダッシュボードログは閲覧できた。
権限追加・新しい認証情報の発行・探索の試行は行っていない。

- Worker version: `dcc5687c-27d9-44d9-ab79-91212bd8ae1b`（NEWS 0.66.0）
- Cron: `30 23 * * *`
- handler開始: `2026-11-12T23:30:42.066Z`（11/13 08:30:42.066 JST）
- handler終了: `2026-11-12T23:30:42.172Z`
- アプリの構造化ログ:

```json
{"event":"news_web_scheduled","scheduledAt":1794526241397,"skipped":true,"reason":"web_schedule_not_planned"}
```

controllerの値は `2026-11-12T23:30:41.397Z`。
計画の `2026-11-12T23:30:00.000Z` との完全一致が成立せず、
`scheduledWebPermit` がD1 claimより前に拒否した。Cron未配信でも、
モデル呼出エラーでも、実行ロックでもない。
プラットフォームの `outcome=ok` は探索成功を意味しない。
ログ基盤の `$workers.event.scheduledTime` は秒表記だが、
アプリの `scheduledAt` とOTelの `scheduled_time` は同一のミリ秒時刻を示す。
ログ表現を混同してアプリで1000倍する修正はしない。

現在配信中のWorker内容SHA256は配備時の証跡と一致:
`7ac917f1173126d6f2272f6df1f3c7fc41a9a1a2f84a7714da5794dfb5e33674`。
GraphQL Analyticsは該当起動を返さず、Cron専用履歴も正常な通常収集を含め空だった。
その空結果から未配信と断定せず、上記の保存済み実ログを根拠とした。

## 修正

`scheduledTime` は整数のepoch millisecondsのまま検証し、予定されたCronの
**分**に正規化して照合する。文字列、秒単位、別の分、別日、計画外は拒否する。
期限は実イベント時刻から15分後ではなく、必ず元の予定時刻から15分後。
08:30:41.397のイベントでも期限は08:45:00のままとする。
1分以上ずれたcontroller時刻は許可しない。予定分内のcontrollerでも、
実行時刻が15分窓を過ぎれば拒否し、過去枠をcatch-upしない。

3枠、各3検索・5推論、合計9検索・15推論、UTC日次キー、D1原子的claim、
既存のロック・失敗時の後続停止・個々の有料呼出直前の期限確認は変更しない。
通常collector、出典条件、正式候補、掲載判断、自動掲載条件も変更しない。
NEWS／Operatorの候補版はバグ修正の0.66.1。

固定head・回帰・最新mainを照合し、既存の並行更新ガードで修正版を配備する。

リポジトリの探索OFF・空計画を本番へ上書きしない。

本番未反映の現在のコードには同じ拒否条件が残るため、次回成功は保証できない。

# PR271：Port本番1.33.0の保持と安全な再統合

## 本番の配備元

GitHub Pagesはmainではなく `codex/port-1.28.0-release-20261106` を公開していた。名前に反して実内容はPort 1.33.0。公開commitは `f26ec11f93561a6dc2164f3f2ecfd2f1b5f81e39`。直前の `b44402e7` がPort 1.33.0、最新commitがStudio Standard入口の停止を保持する公開成果だった。

本番から読み取ったPort／共有依存の公開ファイル215点が、このcommitとすべてSHA-256一致した。対象はHTML、起動・版管理、Sync／Account／認証、テーマ、チューナー、Practice／Calendar、保存処理、静的アセットを含む。認証情報や端末保存データは取得・コピーしていない。

元PR固定head：`d7bd0154ff6562c5c1d19b740cb276780209ffd5`。mainのPort 1.28.0をそのまま配備すると54ファイル（Port52＋共有依存2）の公開済み差分を失うため、その方法は採用しない。

## 再統合方法

1. 54ファイルを、上記の公開済み内容へ戻す。未公開の機能や他のStudio／Sync Worker変更を持ち込まない。
2. 元固定headのNEWS4モジュールをそのまま重ねる。最新JST日1枠＋従来重要度4枠の処理を変更しない。
3. 公開版HTML・起動コードはNEWSの依存キーと必要な版管理キーだけを1.34.0へ進める。Sync・テーマ・チューナー等の実装キーは公開版の値を保持。
4. 本番215点のうち、NEWS4モジュール以外の211点は完全一致、または許された版／起動キーの置換を逆変換すると完全一致することを回帰で検証する。fixtureは実測ハッシュであり、架空の本番成果物ではない。
5. Pagesの配備は公開枝の現在commitへPort変更だけを重ねる。枝全体をmainに置換しない。Port以外の全パス（Studioの公開停止・Pro版・他アプリ・共有依存を含む）は元の公開treeのまま。NEWS Workerはmainの承認済みtreeから別途配備する。

保存コード・schema・移行処理は本番1.33.0と同じbytes。Midnightについては、本番には停止後の再開commit `1893ed06` が既に反映されており、選択肢が表示されていた。その実状態とoverlay/pendingキー処理を維持し、今回新たに停止・再開しない。

## 検証上の区別

* 未変更main：1,286件中1,274 PASS／12 FAIL（元の失敗を再確認）。
* 実際の公開枝1.33.0に旧mainの試験を実行：1,286件中1,200 PASS／86 FAIL。1.28.0の版・テーマ・Sync UI期待値、旧?vキーをimportする試験が含まれ、これを本番の新障害86件とみなさない。
* 再統合後は公開枝の失敗集合にない新しい失敗を認めない。全体PASSと偽らず、比較ログを運用記録へ残す。
* 保存主要スモーク：本番1.33.0／再統合1.34.0の双方で141件PASS。Account変更拒否、未知schemaの保持、保存失敗rollback、asset同期、Practice／Calendar／設定保存を含む。Nodeだけの評価では?vを正規化して1ファイルを同じmodule identityに揃える。異なる版を同時importしてWeakMapが分裂する旧テストの問題と、実ブラウザーのキャッシュグラフ保持は分け、後者は215点の比較で検証する。実端末へ試験データを保存していない。
* NEWS全回帰、Port NEWS、更新・停止・takedown・期限切れ、配備ガード、両Workerビルドを別途実行。reduced-motionの既存CSSを変えず、先頭の新着が静的表示にも残るDOM/CSS契約を追加検証。
* 本番の通常版・Pro版では実際の入口、Account／Syncの表示、既存Practice、Calendar、チューナー／メトロノームの表示、設定を読み取りで前後比較。アカウント切替・データ削除・復旧コード・同期再開・音声許可・記事判断は実行しない。

## 配備の境界

既存guardedActionを使用。main／PR head／ローカルtree／成果物ハッシュ／現Worker版・設定／Pages公開枝を直前に照合する。異常検知でexecuteへ進まない。NEWS配備後は内容hashと実版を照合してからOperatorへ進み、その直後にPagesへ同じ選択ロジックを反映する。両方の反映完了までの一時的な順位差を最終受入と混同しない。

Web探索のGemma・有限3枠・ON、manual OFF、B→A OFF、自動掲載OFF、通常cron、認証、16保護テーブルを維持。migration・追加有料呼出・記事判断なし。設定のOFF／空計画をRepositoryから本番へ上書きしない。

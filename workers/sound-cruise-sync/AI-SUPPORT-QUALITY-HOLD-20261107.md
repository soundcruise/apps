# AI相談の品質HOLD修正と再受入条件

2026年11月7日のPR #222（基準head `93c932aafe577182533a5ddd76f701b9a70ecb38`）の実モデル評価を受けた修正候補。ローカル回帰試験までを実施し、実モデルとiPhoneでの再受入は未実施。本番v143・AI_SUPPORT_MODE=offを維持する。main統合・配備・有料推論は今回の対象外。

## HOLDの原因と証拠

評価モデルは `@cf/openai/gpt-oss-120b`。12ケース、31モデル呼出、入力103,883／出力9,827 tokens、推計US$0.0437293。自動再試行0、usage不明0。

| 分類 | 確認できた事実 | 判断の限界 |
| --- | --- | --- |
| モデルの操作誤生成と検査漏れ | 3件目の最終回答に「注意が出ている Pixel を選んでください。」。Portの同期先一覧に選択操作はない。旧target_selection検査は「選んで」の後、同じ文の24文字以内に別の操作がある場合のみ検出し、この回答を通した | 自動採点もPASSにしていた。単なるプロンプト修正では防止を保証できない |
| 診断の選択不足 | 同期済み・全アプリ未接続の2件は、診断ツールを使わずアプリ名を聞き返した | 診断不能だったのではなく、呼び出すかをモデルに任せていた |
| 全文修正による品質低下 | 7/12件で修正要求、成功2件、5件は汎用の固定エラー案内。原因不明2件と問い合わせ再現ケースも固定案内になった | 中間回答は未保存。5件それぞれがモデルの誤りか、ガードの誤検出かは断定できない |
| 制約の過密化 | 同じ自由文に、状態説明・UI経路・条件分岐・用語制約・問い合わせ導線を同時に要求し、旧UI用の文章検査を全文に適用していた | 制約過多が品質低下に寄与したという設計上の推定。寄与率の実測ではない |
| 待ち時間 | 全体平均12,234ms、最大27,639ms。修正による追加待ち時間は平均9,453ms、最大16,303ms | 新方式の実ネットワーク遅延は未計測 |

保存済み最終回答12件を、合成データだけの `test/fixtures/pr222-hold-final-replies.json` に固定した。元ファイルのSHA-256も記載。実機3件目の実際の相談文と旧回答は既存 `iphone-support-20261107.js` を維持する。当時の完全な会話・ツールJSON・修正前の中間回答を復元したとは扱わない。

## 説明と操作の分離

AIは状態の意味、考えられる確認点、分かること／分からないことを自然な日本語で説明する。画面操作は自由文で生成させず、次の小さな操作カタログから選ぶ。アプリ側が今回の診断結果と表示条件を確認し、確定済みの文面にする。

| 操作ID | アプリが保証する内容 |
| --- | --- |
| inspect_targets | 対象アプリの行の実件数の「同期先N件」を開き、前回報告を確認。詳細を表示できる状態のみ |
| inspect_app | 同期先の前回報告を確認して、該当アプリの「設定 → クラウド同期」を確認。同期データが利用可能で詳細取得済み、不整合なしの場合のみ |
| recheck_app | 「同期先N件」内に「もう一度確認」が表示されている場合のみ案内。実際のPortのretry条件と照合 |
| connect_app | 未接続が診断で確認できたアプリのみ、既存の「同期コード」と「Cruise Portと接続」を案内 |
| check_network | 端末のインターネット接続の確認 |
| preserve_data | データ削除・同期解除を行わず確認する安全案内 |
| contact_support | AI相談画面下部の「メールで報告」。番号・復旧コード・接続コードを書かない注意を併記 |

操作文にモデルの画面名、端末名、URL、ボタン名を挿入しない。未知のID・余分な項目・表示条件不一致は、その操作だけを除外し、正常な説明を残す。解除・削除・名前変更・復旧の操作IDは設けない。聞き返しも少数の確定文から選び、既にアプリが分かる場合や全アプリ同状態での不要なアプリ名の聞き返しは省く。

モデルにはJSONの `explanation / actions / questionId` を要求し、アプリ側でも形を検査する。不正JSONや自由文だけの出力は、そのまま表示せず今回の診断に基づく案内にする。`explanation` に混入した操作文は文ごとに除外し、前後の自然な説明を保持する。これは固有の誤画面名を追加し続ける検査ではなく、操作を専用の出力欄へ分離するための補助検査である。任意の自然言語の全変形を意味的に保証するものではなく、実モデルでの違反率・説明保持率を再受入で確認する。

問い合わせ先など正解が確定した4つの質問表現だけは、既存の本人認証・権限・秘密情報検査を通したうえで、モデルを呼ばず回答する。最重要の旧3件目はこの直接回答に含む。したがって同じ質問のPASSを「GPTが同じ回答を改善した証拠」とはしない。別表現の問い合わせQ3で実モデルの説明と操作IDの選択を確認する。

## 診断と安全境界

- 既存のgetSyncOverviewを先に実行し、今回の質問・直近のユーザー発言で指定されたアプリ、または唯一注意が必要なアプリのgetAppSyncTargetsを追加取得する。最大2診断、すべてSELECT-only。概要と詳細の読み取りの間に状態が変わった場合は、新しい詳細結果を表示・操作条件にも反映する。Accountの選択は認証済みの既存経路に固定する。
- モデルに渡す診断には状態・件数・前回報告時刻を残し、ユーザーが付けた端末名、端末ID、短縮IDを含めない。既存診断ツール自体や同期データは変更しない。端末を名指しする代わりに、実際の同期先一覧と前回報告をユーザーが照合する。
- 通常相談は最大1モデル呼出、確定FAQは0。回答全文の再生成・自動再試行はしない。予想外のモデルツール呼出は実行しない。既存の厳密なツール引数検査と上位の予算上限も維持する。
- ProとAccountの独立認証、β許可設定、rate limiter、送信直前の再帰的秘密情報検査、既知の内部ID検査を維持する。回答中の秘密情報も拒否する。自由文中の任意の個人情報を完全判定する機能を新設したものではない。
- APIは従来と同じプレーンテキストreplyを返し、Port側の表示・一時会話・保存契約を変更しない。通常Sync・D1/R2・認証・NEWS・Studioのコード／配備設定は変更しない。
- 生のモデル応答の記録は合成評価スクリプトの明示的コールバックだけ。HTTP経路には公開せず、本番相談の記録・保存を追加しない。

## ローカル比較

`node scripts/ai-eval/replay-hold.mjs` はネットワークを使わない。保存済みの旧最終文を、明示した合成JSONラッパーの説明欄として新しい表示処理へ通す。これは新モデル出力や構造化出力の実測ではない。旧固定案内5件・秘密情報拒否1件の失われた説明は空欄として扱い、創作しない。

| 指標 | 前回実GPT 12件 | 保存済み回答のオフライン投影12件 |
| --- | --- | --- |
| 修正要求 | 7件、58.3% | 0件、0%（処理自体を廃止） |
| 汎用の固定エラー案内 | 5件、41.7% | 0件、0% |
| 確定したFAQ案内 | 直接回答機構なし | 3件、25% |
| 元の自然な説明を保持 | 中間回答未保存のため保持率は不明 | 2件、16.7% |
| 診断結果からの案内だけになった件数 | 同じ方式で未集計 | 7件、58.3% |
| モデル呼出 | 実呼出31 | 実呼出0。模擬呼出9 |
| 遅延 | 平均12,234ms | モデル／通信待ち時間は評価不能 |

後半の7件を隠して「固定回答0%」とは扱わない。旧最終文の多くが操作・聞き返しだけ、または元の説明が失われた固定案内であり、新方式の自然な回答品質はこの比較では判定できない。

別途、4種類の正常説明×正常／不正操作の8対照では、説明保持8/8、全文固定案内0/8、修正呼出0/8。存在しない選択操作・未知の画面・危険操作を混ぜた文の除外と、実装済み操作の維持を検証した。モック結果であり、GPTの成功率ではない。

Worker全体1,004 PASS、PortのAI相談・同期センター関連82 PASS。ローカルD1の全テーブル内容不変・SELECT-only、認証分離、他Account遮断、秘密／内部IDの各表記、rate limiter、通常SyncのOFF時動作を含む。Wranglerのdry-runはアップロードなしで成功。

## 最小限の有料再受入案

モデルは現行 `@cf/openai/gpt-oss-120b` のみ。前回12ケースを保ち、Q1非実在の選択操作、Q2正常な同期済みの説明、Q3別表現の原因不明＋問い合わせ、Q4削除・解除の提案への回答の4対照を追加する。

- 16ケース、うち3FAQはモデル不要。最大13モデル呼出、失敗時の自動再試行なし。各呼出の応答・usage・最終文・所要時間を合成評価内で記録する。
- 入力4,000／出力900 tokensを各呼出に仮置きすると約US$0.027。計画額US$0.05を提案する。入力長・実usageで変動するためhard capではない。公式単価は入力US$0.35/M、出力US$0.75/M。usage不明が出たら後続の有料呼出を止める。
- 単に危険文が消えたかだけでなく、説明欠落・操作除外・不正JSON・直接FAQを別集計する。通常ケースで自然な説明が失われる、問い合わせ先を答えられない、誤案内や情報漏出が出る場合はHOLDを維持する。
- JSON形式の実モデル互換性、自然さ、正確さ、待ち時間は全回答を目視する。今回のローカル試験から実速度や費用削減率を断定しない。
- 合成PASS後も、本人限定βの配備・有効化・本人確認・実UI最大3問・終了後OFFは別承認。本番コードと他設定を維持し、確実な期限／停止手段を先に用意する。前回指摘された停止保証の課題は、本PRの品質修正では解決していない。

準備済みコマンドの `--dry` はモックのみで無料。`--dry` を外す有料実行は追加承認後に限る。

```sh
node scripts/ai-eval/run-eval.mjs --model gpt-oss-120b --quality-contract --dry --label quality-contract
```

固定モックの16件は14 PASS／2 CHECK。Q3の問い合わせ先不足とQ4の安全案内不足を意図どおりCHECKにするためで、GPT評価の合否ではない。

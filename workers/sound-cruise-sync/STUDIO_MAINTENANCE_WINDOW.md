# Studio backup maintenance window candidate

Normal production remains the fixed v138 OFF artifact (SHA256 de6b6fbd2f759fdc55a32662e10d224e11d876672405b604944270387cc19b15). It has no Control admission dependency. The separate instrumented PR83 artifact is selected only by an explicitly approved maintenance deployment. There is no mutable fail-open switch, timeout-based fallback, automatic deployment, or automatic rollback in this change.

Always-on admission adds a shared failure dependency to Port and all four apps. Reader-only isolation cannot exclude writers to the shared D1/R2 Source. A short, explicitly deployed maintenance window preserves normal availability while reusing the existing admission, effects, invocation, Scheduled/waitUntil, and signed CURRENT implementation. During the window, Control outage or timeout still rejects admission; UNKNOWN remains unresolved. A failed backup can leave the maintenance window in HOLD. A sealed window without verified Archive cannot use the existing reopen command. Never promise an unconditional return time.

The independent maintenance-floor adapter adds a signed window grant to the Production backup runner. It verifies exact Source/Owner/epoch/window/backend, a fresh nonce for each external read, monotonic sequence/head/record/history, and current deployment coverage. The unchanged verified-cutline provider still checks every writer's closure and effects. Empty registry, elapsed time, a disabled cron, or a 100% deployment is insufficient for legacy in-flight, external SQL/R2, old-version/service callers, and manual operations. External attestation must be based on observed facts and responsible operator exclusion, never inferred.

The Source wrapper checks the floor before yielding a page and after consumption. Final acceptance CAS serializes ARCHIVED versus RETIRED. It is required before the trusted sealed-backup operation receipt. The local core can have a SEALED candidate manifest even when the final CAS is UNKNOWN; that alone is not an accepted backup or a restore grant. A fixed operation journal is created exclusively and fsynced BEFORE the CAS. Same-process retries, new-process resume, lost ACK, and stale CAS must not resend. Read-only reconciliation must inspect the original intent/transition ID and external chain. CLOSED, missing, conflicting, or unverified results stay UNKNOWN; no automatic retry. This change does not implement or adopt the live external floor store. Signed callbacks in tests are synthetic, not proof of durable external storage.

Retirement must be durably committed independently before any return to normal. The return validator requires matching RETIRED floor and challenge-bound OPEN evidence, no in-flight/UNKNOWN, stopped Source readers, operator ACK, and exact normal artifact. Its return is candidate-only and grants no deployment permission. Existing direct Control reopen/cancel is not sufficient to authorize normal deployment. Old CURRENT cannot authorize new Source backup after retirement. Historical restore of an already accepted Archive uses its existing explicit archive/target grant and does not require a currently CLOSED Source.

No production profile selects this code automatically. Real floor backend identity, append/CAS/readback implementation, independent verification signer, private Mac-to-operator service caller, capacity/retention/monitoring approval, and window-specific host/execution grants remain deployment blockers. Same-UID, Account administrator, and authority signer compromise are not physically prevented. Never describe a signed provider assertion alone as independent durability or total writer exclusion.

A generic newer runtime adds _cf_METADATA, which correctly fails the strict Production validator. Do not widen the Production schema allowlist to make that fixture pass.

Studio additive DDL, consistent shared-Source backup, and Owner canary have separate approval/stop scopes. This change does not restore shared migrations 0034–0037 as an unconditional initial Studio prerequisite and does not authorize any DDL, Source read/export, freeze, canary, or product deployment.

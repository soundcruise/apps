# 正式実装への引継ぎ — Integrated Score UI Prototype v1

正本は Astra「Integrated Score Architecture Contract v1」。このモックはUI状態の検証であり、コードを製品へ移植しない。
モックの描画（innerHTMLによる紙面生成、手書きSVGの記譜、固定のおすすめ表、スナップショットUndo）は製品品質の実装ではない。

## 1. モックで確かめたUI構造（正式実装で守ること）

1. **入口の分離**: コード名（文字）→ルーペのコード欄。名前付きの「押さえ方」ボタン／TABの該当範囲→フォームパネル。
   ストローク段→リズムパネル。曲情報行→キー・カポのパネル。アイコンだけに頼らず、アクセシブル名を付ける。
2. **フォーム変更の範囲**: 既定は「このコードイベントだけ」。パネル見出しを「1小節目・1拍目の C」と対象イベントで表記。
   変更直後に「同じコードにも適用（ほか N か所：小節番号）」を出し、固定済みは件数を別に示して対象外。固定を含める操作は2段階。
   一括操作は履歴1件。
3. **固定と要確認**: 不適合になった固定の押さえ方は保持し、「要確認」と「固定」を併記。TABには推測したフレットを書かず
   「押さえ方を確認 Dm」の点線枠。おすすめ案はパネル内で並べて見せ、採用は明示操作。
4. **リズム**: 基本8分／16分は具体的な矢印列（拍ごとに区切る）と名前で選ぶ。適用先「この小節だけ／曲の基本」は開いた場所で既定が変わる。
   紙面では継承中も実際のパターンを描き、「曲の基本：…」「この小節だけ：…」を文字で示す。
   ↓↑（鳴らす）・(↓)（空振り）・〜（伸ばす）・・（休み）・止（消音）・×（ブラッシング）を別記号にする。N.C.の小節は矢印を描かない。
5. **自動の音価**: 小節単位の括弧線＋「音の長さ：自動」の文字。音符ごとの警告は出さない。確認するまで残る。
   ルーペのメロディ行で、音を選んで長さを変更、空き時間を「休み」として確定、「この小節の長さを確認」。小節に収まらない変更は拒否（丸めない）。
6. **キー・カポ**: 「何を変えますか？」で4つの目的（移調／実音を保つカポ／押さえ方を保つカポ＝曲全体の移調／表記だけ）。
   必ず変更前後のコード列とメロディ例、固定の押さえ方への影響件数を見せる。固定の押さえ方は自動で置き換えない。
7. **出力状態**: 譜面スタイルに含まれる出力だけを「✓生成可能／△要確認／×生成不可」で表示（記号と文字。色だけにしない）。
   クリックでInspectorの確認一覧、各項目から該当箇所へ移動。生成不可は段の場所に理由の帯を出し、空白にしない。
8. **印刷**: 表示中の全出力が生成可能かつ未確認0なら「完成譜」、それ以外は「確認用として印刷」（各ページの帯・点線枠・括弧線・脚注）。
   「ギター（ストローク・TAB）を除いて印刷」で、確認済みのメロディだけを完成譜にできる。
   選択枠・ルーペ・Inspector・押さえ方ボタン・操作用要素は印刷しない。
9. **画面と印刷の共通レイアウト**: 1システムの小節数・小節幅・改ページは同じ計算から決める。画面にもページ枠を表示する。
   ルーペ用の空きは画面だけで、ページへの段の割り当ては変えない（画面上のページ枠だけが伸びる）。

## 2. ルーペのDOM所有（IME保護）

- ルーペは紙面DOMの外にある**常設の層**。紙面は選択中の段の下に、ルーペと同じ高さの空き（スクリーン専用）を描くだけ。
- 紙面を描き直してもルーペの入力欄は作り直さない。小節を切り替えたら、既存の入力欄の値・位置（grid-column）だけを更新する。
  フォーカス中の入力欄の値は書き換えない。コード・歌詞の変更は `change`（確定時）でだけ反映し、変換中（composition）に紙面を描き直さない。
- 段を移ったときは、選んだ段が画面上の同じ高さに来るようスクロールを補正する（モックでは位置ずれ0px）。
- 高さ700px以下では紙面の外の固定編集領域（画面下）へ切り替える（現行Shellの低高さ境界）。
- 現行の `renderSlotOverlayContent()` は `innerHTML=''` で入力欄を作り直すため、この方式へ置き換えが必要。
  モックは実OSのIMEで検証していない。実装時に macOS/Windows の日本語入力・Safari で確認する。

## 3. 共通レイアウトの規則（モックで使った値。正式値は未決）

- 小節に必要な幅 = 全段の「時間間隔あたりの必要幅」の最大（音符13〜15px、歌詞は文字幅、コード名、ストローク記号、TABの打点）。
- 1システムは標準小節数（4 または 2）を上限に、必要幅の合計が収まるだけ並べる。収まらなければ減らす（文字は縮めない）。
- 小節幅は必要幅に比例して配分。全段が同じ `anchorX(t)`（小節内の時間位置）を共有する。
- 最小文字（100%表示）: 歌詞12px、TABの数字10.5px、コード名13px、ドレミ11px。
- 実測: 「朝のひかり」（8分中心）は標準4でも1システム3小節になった。高密度サンプルは1〜2小節。→ U1の判断材料。

## 4. 正式実装に必要なデータ（Astra schema 2 との対応）

| UI | 必要な保存情報 | Astraの所有領域 |
|---|---|---|
| フォームの状態（おすすめ／固定／要確認）と出所 | イベント単位の割当、採用snapshot、採用方法、確認状態、元素材の出所・削除状態 | `performance.formBindings`、`materials`、`provenance` |
| 自動の音価の印 | 小節（またはイベント）単位の音価の由来と確認状態 | 各対象の `provenance`（auto-assigned / confirmed） |
| 明示の休符と導出の休み | 明示休符イベント | `bars`（melody rest） |
| リズムの継承とこの小節だけ | 曲の基本と小節割当、パターンsnapshot | `performance`、`materials` |
| 空振り・伸ばす・休み・消音・ブラッシング | 発音・継続・方向・空振り・dead stroke・stop を別々に | `performance`（Rhythm contract の要素分離） |
| 空欄・N.C.・前コード継続 | 未指定、N.C.、曲の規則としての継続 | `bars`、曲の規則 |
| 譜面スタイル・段の選択 | 記譜指定（Undo対象） | `notation` |
| 段・小節の選択の追従 | 永続ID（bar / chord event / note） | Stable ID contract |

## 5. 未決のUX項目（モックで比較・判断するもの）

| ID | 事項 | モックで分かったこと |
|---|---|---|
| U1 | 1システムの標準小節数と読みやすさの下限 | 8分中心の歌もので4小節は歌詞幅のため3小節に減る。2小節は余白が多い |
| U2 | Inspectorの幅と1280pxでの扱い | 360px常設で紙面約90%（歌詞が最小文字を下回る）。320pxにするか、1280では重ねて表示するか |
| U3 | カポがあるときのコード名の基準 | サンプルはCapoなしのため紙面では未検証。キー・カポのパネルでは「押さえ方のコード名」と「聞こえるコード」を分けて表示 |
| U4 | キーの表記だけ変えたときのドレミ表示 | パネルに未決として明記 |
| U5 | 音価の確認の単位（小節／イベント） | モックは小節単位。操作は分かりやすいが、部分確認ができない |
| U6 | 空欄コードの規則を尋ねる時期 | モックは最初に要確認が出たとき（帯）。新規作成時に聞く案と比較 |
| U7 | 本棚・マイリズム・高度CAGEDのStandard/Pro範囲と「準備中」の文言 | 入口は準備中として表示。権限が変わっても取り込み済みのsnapshotは消さない |
| U8 | 空振り・ブラッシングの印刷記号 | モックは (↓) と ×。一般的な表記に合わせるか |
| N1 | 押さえ方の番号（C①②）をコード段にも出すか | TABがある譜面だけに出した。コード名が読みにくくなる懸念 |
| N2 | 狭幅の既定倍率 | 600pxで約72%、文字が小さい。100%＋横移動を既定にするか |
| N3 | ストロークの札の文字サイズ | 8.5px（印刷約6.4pt）。読みやすさの下限を決める |
| N4 | パネルの位置 | 押さえ方パネルが紙面の一部を隠す。Inspectorとの使い分け |

## 6. 実装順序への提案（Astra roadmap の工程1→2以降）

1. このモックで U1・U2・U3・N2 を判断し、受入条件を確定（工程1の完了）。
2. 工程2（メロディpreview）の前に、ルーペの常設DOM化（入力欄を使い回す・空きを確保する層）を単独で実装・IME検証する。
3. 工程2で、共通レイアウト（必要幅の集約・改ページ）を画面と印刷の共通処理として作り、モックと同じ配置の意味を再現する。
4. 工程3・5でChord adapter・TAB previewを接続するとき、要確認・未取得・未指定ではフレットを描かない規則をテストで固定する。
5. 工程7〜9で、フォーム／リズムのパネル、音価編集、確認用印刷をモックの画面構造どおりに実装する。

## 7. 停止条件（正式実装時）

推測したフレットの表示、固定の押さえ方の自動置換、空欄コードの暗黙の継続、色だけの状態表示、
自動音価を確定譜として印刷、ルーペの入力欄の作り直しによるIME破壊、画面と印刷で小節配置が異なる、のいずれかが起きたら停止する。

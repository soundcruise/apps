# Integrated Score UI Prototype v1（統合譜面 UIプロトタイプ）

Studio 0.37.0 / project schema1 / 開始基点 `0e651fb938e19e7b74b3c90166ba6d40fbc7bd88`。
Structure譜・メロディ五線・ギター伴奏TABを同じ小節列で扱う統合譜面の、**画面構成と操作性を検証するための独立した静的モック**。

- 製品からは読み込まれない（Studio本体のHTML/JS/CSS、module graph、ナビゲーション、service workerに接続しない）。
- 保存データ・Project Repository・Editing Session・Pro/Account/Authority/Sync・Chord Cruise・Rhythm Cruiseに接続しない。
- localStorage・IndexedDB・ネットワークを使わない。外部フォント・CDNも読み込まない。
- 音楽データは `fixture.js` の固定サンプルだけ。**音楽変換・保存・Undo・おすすめ・印刷は画面状態の模擬**であり、正式機能の動作確認ではない。

設計の根拠は Astra「Integrated Score Architecture Contract v1」と Opus「統合譜面制作 最終UX契約照合と静的モック制作の準備」。

## 開き方

1. Finderで `index.html` をダブルクリック（`file://` で動く。ビルド・サーバー不要）。
2. 右上の「検証パネル（S01–S24）」から状態を選ぶ。URLの `?s=S13` でも直接開ける。
3. 比較用の設定（検証パネル内）: 1システムの標準小節数 4/2（`&bars=2`）、Inspectorの幅 360/320（`&insp=320`）。

既存の8765/8766サーバーは不要で、使わない。ローカルサーバーで開く場合は別のポートを使う。

## ファイル

| ファイル | 内容 |

| `index.html` | Shell・Toolbar・出力状態・紙面・ルーペ（常設DOM）・Inspector・検証パネル |
| `prototype.css` | Studioのトークン値を写したスタイル。幅の境界は現行Shellと同じ（1280/800/600px・高さ700px） |

| `notation.js` | 共通レイアウト（小節幅・1システムの小節数・改ページ）と五線・TAB・コード段のSVG描画 |
| `app.js` | 画面状態、ルーペ、パネル、模擬Undo/Redo、印刷プレビュー、S01〜S24 |
| `HANDOFF.md` | 正式実装への引継ぎ |

## 固定サンプルの音楽内容（整合を確認済み）

- 「朝のひかり」（このモックのための書き下ろし。既存曲ではない）。Key C・Capo なし・♩=92・4/4・12小節。
  - Aメロ（1–4小節）: ドレミ文字入力から自動で割り当てた音価（未確認）。現行Studioの配置規則（8分枠に順に置き、〜で直前を延長）と一致する並び。
  - サビ（5–8小節）: 確認済みの音価（付点4分・2分・明示の休符を含む）。5–7小節は1小節2コード。
  - アウトロ（9–12小節）: メロディなし。7小節目のG（E型・3フレット）と12小節目のC（本棚から取り込み・元は削除済み）が固定済み。12小節目は「この小節だけ：1回鳴らして伸ばす」。
- 「高密度サンプル」4小節: 1小節4コード、16分音符の連続（C4の加線を含む）、英語の歌詞、6種類のストローク記号、16分・王道。
- フォームは6弦→1弦のフレット（Capo相対）。全フォームの構成音がコードの音だけであることを確認済み（C/G/Am/F/Em/Dm7/Dm/G7、CのCAGED 5形と開放の別形）。
- ストロークの使用弦はサンプルの演奏指定（ダウン＝フォームの全弦、アップ＝1〜3弦）。TABの数字はこの指定とフォームからだけ作る。
- 要確認・未指定・おすすめ表にないコードでは、**TABに数字を書かない**（推測したフレットを表示しない）。

## 検証結果（使い捨てChrome・空きポートの一時ループバックサーバー・外部通信遮断）

- S01〜S24 すべて到達。console error / warning 0、404 0、外部へのリクエスト 0（読み込みは本ディレクトリの7ファイルだけ）。
- ページ全体の横方向のはみ出し: 1920 / 1440 / 1280 / 800 / 600px すべてなし。
- ルーペ: 選択した段を覆わない（S09・S10・S15）。小節移動・段移動・紙面の再描画の後も同じ入力欄が残り、フォーカスが保たれる。段を移っても画面上の位置ずれ0px。
- キーボード: Tabで小節に到達、Enterでルーペ、Escでルーペ／パネルを閉じて元のボタンへ戻る、⌘Z・⇧⌘Zで模擬Undo/Redo。
- 印刷: `@media print` の実出力（PDF）のページ数がプレビューと一致（S20 確認用2ページ、S21 完成譜1ページ）。選択枠・ルーペ・押さえ方ボタン・操作用要素は含まれない。
- 固定サンプルの整合: 音価の合計・拍の分割・フォームの構成音・移調の綴り（例 C→Capo2実音保持で B♭ F Gm E♭…）を別スクリプトで確認。
- Studio本体の Node テスト 870件 PASS（プロトタイプ追加による影響なし）。

| 幅 | 配置（弾き語り譜） |
|---|---|
| 1920px | 紙面150%（上限）。左右に余白 |
| 1440px | 紙面150%。Inspectorを開くと重ねずに縮小 |
| 1280px | Inspector常設で紙面約90%（Inspectorなしでは約135%） |
| 800px | ナビの補足文を隠す。紙面約80%。パネルは下からのシート |
| 600px | ナビが上段（横スクロール）。紙面約72% |

未確認: Safari、実OSの日本語入力（IME）、実プリンター、利用者のズーム設定。静的モックでIME対応を保証したとは扱わない。

## 既存Studio（0.37.0）との違い

| 項目 | 現行Studio | このプロトタイプ |
|---|---|---|
| 呼び名 | ナビ「Structure」、見出し「譜面クルーズ」 | 「譜面」に統一（内部IDは変更不要） |
| 紙面 | A4コード譜1種類 | 5つの譜面スタイル。五線・TABを同じ小節列へ統合 |
| 曲情報 | 折りたたみ欄に表示設定と混在 | 紙面の曲情報行をクリック（キー・カポは目的別パネル） |
| Toolbar | 新規・元に戻す・やり直す・保存・印刷・JSON書出・JSON読込を同列 | 曲・Undo/Redo・譜面スタイル・保存・出力の5まとまり。バックアップは「曲」メニュー内 |
| ルーペ | 紙面の上に浮かぶ。小節切替で入力欄を作り直す | 選んだ段の直下（紙面に空きを確保し、紙面DOMの外の層）。入力欄は使い回す |
| ストローク | 継承中は点（・）だけ | 実際のパターンを表示し「曲の基本」「この小節だけ」を文字で示す。6種類の記号を区別 |
| 状態 | 保存状態のみ | 出力ごとの生成可能／要確認／生成不可、確認一覧、確認用印刷 |

## このモックで行っていないこと

正式な音楽変換、Chord Cruiseの推奨処理、Rhythm Cruiseの公式パターン取得、保存、正式Undo、キー・カポ変更の実行、
ギター伴奏五線の記譜、本棚・マイリズムの読み込み、手での押さえ方編集、PDF生成機能、Pro判定。

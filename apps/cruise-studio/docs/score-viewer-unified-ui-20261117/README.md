# 譜面クルーズ／譜面ビューワーの操作・音設定を統一

2026-11-17。Studio local **0.155.0-dev.1**、Viewer **0.12.0-dev.1**。基準`82e4e8a7`、`codex/score-toolbar-ui`。先行0.152〜0.154の未コミット差分を保持。正式Studio0.88.1、ファイル形式v1、ライブラリDB v3は維持する。本番配信・公開HTML・実Account・認証／Sync設定・Workers・ニュース・他アプリへ変更を広げず、コミット・pushもしない。

## 今回の操作

- ライブラリの「編集」切替を廃止。フォルダ作成、名前・格納先、複製、削除、PCのドラッグ移動を常時利用できる。削除は確認を挟む。譜面の音楽データは変更しない。
- 下部カードは再生・反復、BPM、音モードを近くにまとめた。BPMと音モードには別の外枠を設け、狭い端末では音モードを1つの選択欄にする。320px縦／844px横でも1行に収まる。
- メニューの「表示」に表示設定、全画面表示、配置、拡大・縮小を集約。配置と拡縮はラベル＋操作欄の行とし、「書き出し」は下側へ分離した。PDFは構造上できない表示切替や音設定を出さない。
- 小節選択・範囲・再生小節・現在地の棒を両画面で落ち着いたゴールドへ統一。単独選択の通常再生は現在小節へ進み、範囲ループでは選択全体を維持する。
- 両方の音設定に再生ボタンを追加。コード／メロディ／メトロノーム音量を再生中に変更できる。「音と棒の同期」の0〜1000msスライダーは常時表示する。追加遅延だけ解除する「自動に戻す」を用意する。
- ユーザー回答どおり、譜面クルーズは**停止**、ビューワーは**一時停止して続きから再開**する役割を保持する。ビューワーは譜面版別の閲覧設定、編集側はブラウザ全体の練習設定という保存単位も維持する。どちらも元Project／JSONの音楽内容へ混ぜない。

## 共通化と不具合修正

`score-ui.mjs`に配色、棒のtransform配置、再生ボタンの状態表示、外側クリックを集約した。`score-audio.mjs`は出力装置時計とサンプルの無音接頭部除去だけを共有する。表示時計はgetOutputTimestamp（未対応時はbaseLatency＋outputLatency）を使い、発音予約のcurrentTimeと分離する。譜面クルーズも同じ音源先頭補正と出力時計を使う。音程、ストローク内の弦順・間隔、既存の発音計画は変えない。

譜面クルーズの紙面カーソルは小節内のDOMを作り替える方式から、紙面直下の**同じ1本**をtranslate3dで動かす方式へ変更した。小節境界、拡縮、周回でもノードを保持し、停止と印刷で除去／非表示にする。編集マス上のガイドは残し、色と時計を共有する。

WebKitで音設定内の再生を初回クリックできない場合があった。毎フレーム同じボタン文言を書き換え、focus中にclick対象を入れ替えていたため、状態が変わった時だけDOMを更新するよう修正した。専用ボタンのpointerdownでは先行focusも防止する。キーボード操作は保つ。

## 外側クリック

音設定・送り設定・ライブラリ・PDF設定・ヘルプ・書き出し確認などへ共通処理を適用した。表示設定は未保存プレビューを取り消し、音量や送り設定の即時反映値は保持して閉じる。保存／書き出し／移動の処理中は既存のbusy保護を維持する。フォームの未確定変更も既存の適用／取消契約を維持する。

押し始めと離した位置が両方外側のクリックのみ閉じる。スライダーを内側から外へドラッグしても閉じない。外側クリックは下の譜面への選択操作に流さず、その場で消費する。別のdialogを操作している時も閉じない。

## 配布境界

Studioパッケージの明示依存一覧へ共有2モジュールを追加した。Viewerファイルを含めない既存Studioパッケージでも音設定が欠落しないための依存管理であり、公開・配信・認証設定の変更ではない。依存境界ゲートとパッケージ内容試験を維持する。ローカルViewerの静的265依存だけを再生成し、Service Worker自体は変更しない。

## 確認

Node **2,341成功・失敗0・既存スキップ1**、Python模擬ストア **9成功**。Chrome／WebKitのViewer通常回帰 **182成功**、編集側の関連 **79成功**、実サーバー停止によるオフライン起動 **3成功**、合計 **264成功・失敗0**（親ケースを含む。再試行を加算せず、旧前提の失敗ケースは最終成功結果に置換）。

設定内の初回再生、再生中の音量・表示遅延、Stop／Pause、外側クリック、ドラッグ中の維持、表示取消、元譜面・履歴・原本bytesの不変、小節境界／ズーム後の同一カーソル、縦横レイアウト、フォルダ整理、PDF保存／印刷入口、模擬SyncのCAS／破損／容量失敗を確認した。

模擬受信した譜面・PDFを保存し、サーバーを実際に停止。Chromeのブラウザ再起動とWebKitの新規ページで譜面・音源・日本語PDF・Portを確認し、同じURLへfinallyで復旧した。実Syncは使わない。最終静的依存は`0.155.0-dev.1-ba87663f51bb`、265ファイル／12,301,728bytes。

[試験内訳・ローカルログの対応](verification.json)。主な最終ログは`/private/tmp/viewer155-node.log`、`viewer155-unified-pdf.log`、`viewer155-sync-navigation-final.log`、`viewer155-playback-forms-final.log`、`viewer155-cold.log`。通しログの旧UI期待値による失敗は、上記の対象別最終成功結果で置換する。

Safariの既存localhostタブでも、常時編集ライブラリ、BPMグループ、メニューの各項目、音設定の再生入口を確認した。ユーザーの譜面・フォルダ・設定値を変更せず、一時停止状態で終了した。実スピーカー／Bluetooth機器ごとの聴感、実スマホ、OSの実印刷は今回の保証範囲ではない。

初回のUI試験ではメニュー内の拡縮欄に16pxの横あふれを検出し、メニューの幅とグリッド最小幅を修正した。非同期保存後のライブラリ試験は操作が有効に戻ることを待ってから外側をクリックする。旧追従試験の時間注入も、消えた式への置換を検知できるようにして新しい表示時計へ接続した。「準備・設定」が開いたまま下の保存／Portを押す旧試験も、最初のクリックで閉じるだけとなる新仕様へ更新した。旧来の青や「再生ボタン単体が厳密な中央」という期待値は、承認されたゴールドとクラスタ中央配置へ更新した。

# フォルダ書き出し・表示／再生設定・フォーム閲覧

2026-11-17。Studio local **0.156.0-dev.1**、Viewer **0.13.0-dev.1**。基準`82e4e8a7`、`codex/score-toolbar-ui`。先行0.152〜0.155の未コミット差分は保持。本番・公開HTML・実Account・認証／Sync設定・Workers・shared・ニュース／他アプリは変更しない。コミット・pushなし。

## 操作

| 対象 | 変更 |
|---|---|
| 譜面クルーズからの書き出し | 名前・フォルダの確認画面を追加。その場で選択フォルダの下に新しいフォルダを作成し、選択して書き出せる。指定なしは未分類。同名の別名／上書き／取消は維持し、上書きもフォルダを確認する。 |
| ライブラリ | 「格納先」を「フォルダ」に統一。最大幅820px、フォルダ列190pxに調整。色付き25pxアイコンと大きめの文字、新しいフォルダは列の先頭へ。 |
| 複製 | 編集画面を開かず、同じフォルダへ`(2)`、`(3)`と自動追加する。既存の番号付き名からの複製でも番号を重ねない。原本データは共有しても、閲覧設定・表示名・版の参照は独立する。 |
| 名前・フォルダの変更 | ライブラリの上に幅400px以下の小さなウィンドウを表示。外側クリックはこの編集だけを取り消し、親ライブラリは残す。既存のフォルダ階層・競合・循環・削除保護は維持する。 |
| メニュー | ビューワーの配置セレクトと拡縮枠を44pxへ。譜面クルーズは左上の「メニュー」へ改称し、ファイル／表示／再生／曲の設定／書き出しに整理。表示・表示設定・拡縮・再生設定を追加。再生はViewerと同じゴールドにした。 |
| 音設定（両画面） | クリック／ウッド／電子音を選択可能。同じローカル生成音を共有し、外部音源を取得しない。音量・拍計画・BPMは分離する。同期スライダーは−1000〜＋1000ms。マイナスで棒を早め、プラスで遅らせ、0へ戻せる。 |
| 表示設定（両画面） | 「小節ハイライト」「再生の棒」の色を追加。キャンセル、保存、プリセット共有に対応。色は6桁hexのみ許可し、CSS／URL等は読み込まない。 |
| ビューワーのフォーム | 譜面内のフォームから閲覧専用の拡大画面を開く。キーボードでも開け、閉じる／外側クリックで終了。編集ボタンや運指変更はない。画面を離れた時も閉じる。 |
| フォーム一覧（両画面） | 曲末の独立した表示項目。表示設定からON/OFF。初期はOFF。同じコード名・同じ実フォームを1つにまとめ、別運指は残す。一覧からも閲覧専用で拡大できる。横表示では一覧の幅を抑えて左側へ追従させる。 |
| PDF | フォーム一覧を末尾へ含め、図の途中で改ページしない。通常の譜面フォームと同様、SVGを事前画像化する。PDF作成用の非表示領域は、ボタン・tabindex・クリック操作を持たない。 |

「停止」と「一時停止して続きから再開」は前回のユーザー回答どおり維持する。Editorの音設定はブラウザ設定、Viewerは譜面版別の練習設定。表示の追加値は既存の表示専用データに保存し、音楽Project／履歴／JSON／MIDIを書き換えない。ファイル形式v1・ライブラリDB v3・正式Studio0.88.1は維持する。

## UI案の判断

今回、メニュー・曲名・表示／拡縮を上段、再生・再生設定・保存・履歴を次の段に揃えた。Viewerは演奏中心、譜面クルーズは小節操作も必要なので、既存の編集操作を上部に残している。

次の調整案は、再生・再生設定を両画面共通の下部バーへまとめ、保存・Undo・履歴を譜面クルーズの上部に残す構成。再生位置を常に同じにできる一方、編集画面の下端や鍵盤との重なりを検証してから採用する。今回はこの下部移動までは行わない。

## 検証

全Node **2,344成功・失敗0・既存スキップ1**。最終の共有依存境界等も **12成功**（Node総数に重複加算しない）。Python模擬ストア **9成功**。Chrome／WebKitは新規UI14、Viewer既存182、編集関連79、実断オフライン3＝**278成功・失敗0**。親ケースを含み、再試行は最終結果で置換して重複加算しない。[ログと内訳](verification.json)。

書き出し時の新規フォルダと実際の保存先、番号付き複製、上に重なる小さな編集画面、表示の取消／保存／共有プリセット、色・同期の安全な正規化、異なるメトロノーム波形、範囲・停止／再開・音量・履歴・フォーム編集の既存操作を確認した。元Projectとライブラリ原本の不変、古い保存値、容量・競合・破損、模擬Syncの既存境界も維持する。

旧テストは、複製直後に編集画面が出る前提、上書き先フォルダの確認がない前提、フォームも含め全要素がキーボード操作不可という前提を更新した。小節選択はフォームを避けた位置をクリックし、フォーム部分では拡大することを別に検証する。共通メトロノーム音の試験タグは、旧読込関数だけでなく実際の発音予約位置へ接続した。WebKitの画面遷移待ち1件は同じ実操作で再確認成功。PDF試験の1回目は終了処理が待機し続けたため意図的に停止し、独立した最終実行で20件成功した。

12小節の合成曲＋フォーム8種類のPDFは両エンジンともA4 **2ページ**。Chrome約459KB／WebKit約647KB、末尾ページの一覧をPopplerで描画し、見切れ・暗い背景・図の欠落がないことを目視した。独自譜面のPDFは従来どおり画像形式で、文字検索／選択はできない。OSの実印刷は行っていない。

最終候補の静的265依存（12,318,690bytes、`0.156.0-dev.1-fd8efbcf1863`）を準備し、ローカルサーバーを実際に停止した。Chromeのブラウザ再起動／WebKitの新規ページで模擬受信した譜面・音源・日本語PDF・Portを確認し、同じURLへ復旧した。実Syncには接続しない。今回、ユーザーの既存ブラウザ内ライブラリを操作・書き換えていない。

ローカル確認先: http://127.0.0.1:18874/ ／ http://127.0.0.1:18874/apps/score-viewer/local/ 。実機の聴感同期・Bluetooth・スマホ実機・OS印刷は未確認。同期のマイナス／プラスは表示位置だけに適用する。

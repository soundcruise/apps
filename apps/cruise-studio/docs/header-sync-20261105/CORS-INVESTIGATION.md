# PR #197 WebKit reload fixture

The original PR head was `b29561c3260c2c865140f0799dcb1da252f38430` / tree `349e02af89e2107d01f6d73dbe5daaaf9c15479e`. Investigation used disposable synthetic Account/Project data and Miniflare; the Playwright context installs `route('**/*')` before page creation, serves the production-shaped hostname from local artifacts, routes API calls to Miniflare, aborts other origins and blocks Service Workers. Miniflare outbound is forbidden.

The affected request is `POST https://sound-cruise-sync.cruise-port-requests.workers.dev/v2/pro-auth/device-session/challenge`, Origin `https://soundcruise.jp`, Content-Type `application/json`. The normal client path is Studio entry -> shared Pro device-session validation -> challenge. Recorded synthetic 200 responses had `Access-Control-Allow-Origin: https://soundcruise.jp`, `Access-Control-Allow-Methods: POST, OPTIONS` and allowed `Content-Type`. Browser interception did not report a separate OPTIONS request, so the presence or absence of a browser-internal preflight cannot be inferred. A separate direct synthetic Worker OPTIONS check asserts the actual preflight response and relevant headers.

Instrumented failing WebKit execution recorded an explicit reload at t=0ms, a challenge POST at +1ms, `requestfailed: cancelled` at +2ms and a WebKit access-control page error for the Project request at +3ms. The intercepted challenge completed with synthetic 200 at +4ms, after the old page had cancelled it. The second immediate reload also cancelled an in-flight Project POST. Prior failures included the challenge access-control message itself. This supports a navigation/request cancellation race in the test sequence rather than evidence of a rejected Pro credential; it does not establish the cause of every possible CORS failure. The context route remained registered across reload; no error handlers, assertions or browser errors were suppressed.

One matched comparison in each of Chrome and WebKit, with the same two reload actions at the same initial fixture point, passed on both #195 baseline and #197 candidate. That comparison did not reproduce the intermittent failure; it does not prove the baseline cannot exhibit it under other timing. Product authorization and transport code are unchanged between the two candidate revisions.

The fixture-only fix waits for Playwright's existing network-idle event before each of the two sequential reloads. It does not increase a timeout, retry, bypass authentication, change a CORS response, or relax the zero-error assertion. A separate direct OPTIONS assertion verifies the preflight contract in the synthetic Worker.

After the fix, three independent WebKit runs and one Chrome run each passed all 31 product checks with zero captured page errors. These include Home and sidebar Sync navigation, Account observer, Project Cloud, draft protection, reload, four app hosts, score and Pre-DTM. Regenerated canary matches the committed 90 files by SHA-256; normal Studio matches main 81/81. The actual iPhone/Safari and real Account/Project Sync remain untested by this fixture.

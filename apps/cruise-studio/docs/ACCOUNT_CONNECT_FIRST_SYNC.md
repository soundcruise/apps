## Reproduction and smallest correction

The #152 repository captured its Account baseline once in its constructor. It correctly blocked an A form under B, but also blocked null-to-A registration, A-to-null disconnect and a legitimate first native Sync receive into a document started without an Account. A direct repository reproduction rejected all three; the new real Standard product scenario against the exact #152 native root failed its post-connection Gear save. This was a product guard defect, not an image validator or new server contract requirement.

Keep the existing final commit guard, native Account DB/generation comparison, rollback, caller guard validation and stale-notification checks. Capture an in-memory Account context at Gear/category/My Apps/Practice form creation (and Practice detail/file operations), and forward it through existing stores/workflows. A fresh write without a retained form context captures the current operation's Account. Native Sync retains its existing runtime `assertCurrent` / Account revalidation before local apply. Neither the `source` label nor merely having an Account DB grants a bypass. No new grant, persistent Owner record, adapter or save path was added.

An anonymous form can bind to its first connected Account. A retained A form cannot commit under B, and can resume under the original Account/Device/credential. Same-identity reauthentication remains valid. An Account generation change during a save still rejects, including an A-to-B-to-A change during preparation. Explicit disconnect permits local-only writes, as before #152; it does not erase a retained A form's context for a later B connection. An Account read invalidated while capturing a particular form fails closed, preserving input; reopening that form captures fresh context instead of permanently poisoning the whole document.

Gear/category/My Apps/Practice create/edit saves, My Apps/Practice deletion, Gear staged photo persistence, and Practice attachment preflight use the retained context. Fresh list/settings operations continue using operation-time context. This is not a new persistent per-Account partition for every historical device-local dataset, nor a claim that arbitrary cross-Account adoption is safe. Existing native runtime invalidation still isolates A pending work from B. The existing Account-switch and caller-guard tests remain.

Removing the entire #152 guard would reproduce the known A-form-under-B defect. The selected change preserves that guard and fixes its lifetime/placement using existing repository operations. Most changed Port modules contain only required canonical import cache keys (1.24.23 to 1.24.24); they are not a Port 1.28.2 feature transplant.

## Product acceptance and fixtures

The product suite uses the actual Studio release page and native Port Standard/Pro pages, disposable Chrome profiles, existing native Account APIs (including real synthetic Port invitation issuance/consumption), device-bound Pro verification and local copied DB/R2 fixtures. It never reaches Production. Standard Account registration does not gain Pro Sync. New cases cover same-page registration/local saving, first Pro Sync, another-device invitation join/first receive in standalone and Studio, and disconnect/local saving. Existing 25 cases retain A-to-B-to-A, fresh B saving, old form refusal, category/My Apps/Practice/attachment preservation, two-way Gear/asset Sync, revocation and offline grace.

Fixture corrections preserve product behavior: native remote receive can reload a standalone Port document; completion now observes that navigation or the existing enabled Sync action, rather than waiting forever for a hidden action in the new Home document. An artificial Account switch waits for the form's actual asynchronous Account capture to complete, so it tests a captured A form rather than a deliberately invalidated capture. The native Pro gate helper submits input and invokes the unchanged native button handler in one browser task; the former separate fill/click commands intermittently reached a cleared input during terminal-revocation/modal transitions. No authentication result, qualification or server acceptance is injected by this helper, and timeouts were not extended.

Two pre-helper-correction full runs passed 30/30; a further run stopped on that existing gate fixture transition. Final runs and all intermediate failures are distinguished in `account-connect-first-sync/validation.json`. Do not describe a partially completed run as a full PASS. The separate recovery/assets suite passed 12/12 twice. Node root retains the four exact-main theme failures (unchanged CSS and test); they are not skipped or weakened. Nested Port and selected shared/entry tests pass. UI tests cover all five themes, 1440/1024/768/390, native apps, central/right movement, unsaved refresh guards and single-owner audio handling. Actual microphone/Safari/real credentials are not included.

指板表示の瞬間的変化 — 調査・修正候補 Studio 0.86.1
2026-11-07 / base main 565c25e562d6d3302d39c19b1aaab321094ac551

判定: CONDITIONAL PASS（Draftレビュー可、公開承認ではない）

再現
公開Studio Pro 0.86.0のSafariプライベートウインドウで、指板をたどる
STAGE 1開始時の4→3→2カウントダウン中に指板全体が段階的に縮小した。
指板クイズSTAGE 1でも、最初の問題表示後に指板全体が縮小した。
双方を連続PNGで記録。公開のFretboard 2.27.1 script/themeとmainの同一性を確認。
指板単体Pro 2.27.1のSafariでは、通常・低いウインドウの開始時に同じ縮小を
観測しなかった。単体全条件の不存在を証明する結果ではない。
今回Windows VMは追加操作していない。タップ遅延は対象外。

原因と因果比較
Studio js/core/native-port-presentation.js の共通高さ調整は、内容に合わせて
iframe.heightを変更し、内部app-containerをheight:auto!importantへ変える。
指板はviewportの高さを読み取って投影倍率を決めるため、出力の高さが次の
入力の高さへ戻る循環になる。開始・問題遷移・親DOM変更・resizeで再計算される。
srcdocはlocation.originがnullなのでbindの監視登録前にreturnするが、docは
代入済みであり、親のplacement observer等からupdateが呼ばれる経路は残る。

隔離fixtureはStandardの実際のscript/theme、Studioの表示CSSと上記高さ調整を使用。
Pro認証を偽造せず、Account/Syncホストや資格を注入しない。親のclass更新を
毎秒発生させ、Studioの共通更新から高さ調整が呼ばれる条件だけを作った。
初期指定は1300×450。旧高さ調整では756→561→493→475px等に変化し、
同じ5弦ドのカウントダウン中にscale 1.4428→1.1978→1.1331を記録。
修正後は高さのinline上書きなし、viewport 1300×450、カウントダウン4/3/2/1と
通常進行でscale 1.1763が一定。Chromium 157の観測値でありSafari実測値と混同しない。
観測用コードは作業フォルダResults内だけ。製品配布へ追加していない。

修正
共通高さ調整からdata-studio-app=fretboardのdocumentだけを除外する。
既存の高さ上書きがあれば除去し、元のiframeの高さ・指板側のscroll管理へ戻す。
中央と右側paneのいずれも指板の本来のviewportを維持する。
機能差分はnative-port-presentation.jsの1条件のみ。
Studioを0.86.1へpatch更新し、既存のversion/cache参照と生成Pro入口を揃えた。
Portは1.28.0、Fretboardは2.27.1のまま。

正常演出との区別
対象/次の音の青・緑のマーカー、弦の強調、正誤色、カウントダウン数字は残す。
問題と結果の間で指板全体の投影サイズが変わる現象を修正対象とした。
描画DOM、学習判定、ステージ進行や既存アニメーションは編集していない。

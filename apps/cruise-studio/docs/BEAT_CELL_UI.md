# 拍別入力と確認ダイアログの調整

ローカル候補0.88.3-dev.1。既存候補44bd7463を保持。

- 歌詞の最終セルEnterによる次小節移動を廃止。コード／ドレミは1小節1欄から8分／16分セルへ変更。Enterは同じ行の次セルへ進み、末尾は停止する。
- ストロークは既に入力した記号をEnterで循環させず、次セルへ進む。位置移動は既存のSession／content guard付きfocus予約を使用。
- コードとドレミは既存schema2のイベントをonsetTickで直接指定し、Session単一履歴へ文字入力をまとめる。保存形式やMusic Model基本構造、Repositoryは不変更。
- コード挿入は明示した新しいコード位置を境界とし、前のコードのdurationが重なる場合だけ短縮。同じ操作のUndoで元に戻る。元イベントIDは保持。新コードの未指定durationは未指定のまま。
- 既存メロディのpitch編集ではID、音価、時間の確認状態を保持。新しい音はセル幅の仮音価としてauto-assigned／未確認。既存の持続音・休符に重なる新音の挿入は拒否し、切り捨てない。セル内の細かな位置や複数イベントは読み取り専用で保護。
- 1セルのドレミは1音。複数音をまとめた文字列と伸ばし記号による音価再配置は受け入れず、詳細音価は既存メロディInspectorで編集する。
- 紙面は全コードをonset位置で表示する。解像度切替・表示だけではイベントを変更しない。
- IME中／229／composition直後はEnterで移動せず、不正入力はbufferを保持し、移動・保存確認の続行を拒否する。入力欄内のnative Undoは独立した文字入力groupとして扱う。
- 未保存確認の本文・ボタン間に24px、ボタン同士に16px、内側に追加12pxの余白を設ける。390／1440pxの画像と長いProject名で確認した。

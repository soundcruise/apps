## 操作と原因への対応

- フォームの大きさの差は、次のコードまでの空き幅に合わせて図を広げたため。全登録フォームで共通の列幅を使い、3/4フレットの描画領域も揃える。16分位置のコードがあれば共通列を細かくする。図の高さも列幅に追従させ、余分な空白を残さない。5フレット以上の広い図は同じ枠に収める。
- 譜面のフォームは指番号を省略。コード名または図をクリックすると、中央の拡大ダイアログで指番号まで確認できる。図のEnter/Spaceでも開き、閉じる/Escで戻る。読取りだけで、登録・保存・確認状態やUndoを変更しない。未登録コードを自動生成しない。
- 小節の余白クリックは選択だけ。「編集する」または小節上のEnterで編集カードを開く。選択ボタン専用に小節番号の帯を確保し、末尾コードと重ならないようにする。印刷ではボタンと専用余白を省く。
- コードクリック＝フォーム拡大、余白クリック＝小節選択、という役割に分けた。編集カードを開いたまま別の小節余白をクリックしても、選択までで止める。未確定/不正入力/IME/競合/保存中は切り替えない。
- 編集カードの×を左端へ移動。右窓ボタンは右端を維持。閉じる操作でも入力保護を維持する。
- 再生帯の位置から半マス分を引き、再生ヘッドを帯の中心に配置。ストロークのspanに対する背景解除CSSが帯にも適用されていたため、帯を解除対象から除外した。印刷には帯と棒を出さない。

## コピーと貼り付けの契約

同じProjectの1小節を対象とする。小節を選択し、⌘C/⌘V（Mac）またはCtrl+C/Ctrl+V（Windows）、上部の「コピー」「貼り付け」を使用する。複数小節のコピーとProjectをまたぐ貼り付けは対象外。入力欄内は通常のテキストコピーを優先する。

コピーはSessionごとにメモリ内へ保持し、OSクリップボード・localStorage・Repositoryへ書かない。再読込み後はコピーし直す。貼り付けは対象小節の内容を置き換える。小節数・貼り付け先の小節ID/所属セクション/改行を保ち、コード・歌詞・メロディのIDと必要な内部参照を新規にする。フォームとストロークも元の参照/内容を保持し、studioストロークの素材・slot IDは独立させる。コピー時点の継承リズムも保ち、その後の基本リズム変更に化けないよう小節へ結び付ける。

既存のschema2 duplicateBarとSession.runOperation(requireUndo)を再利用。実Projectの小節を一時的に増減せず、貼り付け全体がUndo 1回。貼り付け直後に紙面と編集投影を更新する。旧素材を改変・削除しない。楽器条件変更、素材の不一致、不正データ、古い対象、履歴容量不足は失敗として原状を保持。保存失敗でも貼り付けdraftとUndoを保持する。

schema2、Music Model、Repository CAS、保存形式は変更なし。本番認証・Account/Sync・Coming soon・公開HTML・Cloud/Worker/D1/R2・配信設定も不変。18874のbind/Host/CSPと専用アダプターの公開除外を維持し、サーバーは停止していない。実ユーザーデータは試験に使わない。

## ローカル確認

保存したいdraftを保存し、http://127.0.0.1:18874/ を再読込みする。

1. 「フォーム」をONにして図の共通サイズを確認。コード/図をクリックし、拡大時にだけ指番号が見えることを確認。
2. 小節の余白をクリック。「編集する」だけが表示されること、同ボタン/Enterで編集でき、×が左端にあることを確認。
3. 短いテスト小節をコピー→別小節を選択→貼り付け。全行とフォームを確認し、Undo/Redo→明示保存→再読込み→JSONを試す。貼り付け先の内容は置換される。
4. 再生時の棒が帯の中心にあり、譜面のストローク行にも帯が見えることを確認。

追加実装はしていないが、次の候補は「左右キーで小節選択」「同じコードのフォームを省略して変化点だけ表示」。コピー先選択の効率と譜面の混雑を改善できる。既存のセル内左右移動との競合は、編集カードを閉じた紙面選択時だけに限定すれば避けられる。

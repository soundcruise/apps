# 音と棒の同期・連続再生の確認

2026-11-17。基準85fbdaf0、codex/score-toolbar-ui。使用モデルSol。先行の通し操作試験と記録を保持。Studio local 0.160.2-dev.1 / Viewer 0.16.0-dev.1。公開版Studio0.88.1、譜面format v1／preset v1／library DB v3は維持。

## 修正

譜面クルーズで1小節を選び、明示的に反復をONにして再生すると「連続する複数小節を選択してください」となり開始できなかった。下部の反復ボタンは1小節を対象にできるが、buildRangeLoopPlanが旧仕様の2小節以上を要求していた。

同じ範囲検証で1小節以上を受け入れるよう修正。範囲外・0・非整数は引き続き拒否する。1小節／複数小節／全曲の音楽・発音位置・loopPeriodは同じ計画から作る。複数選択時の自動反復、Editorの停止／Viewerの一時停止、練習テンポの保存境界は維持する。

Chrome／自動WebKitの専用UI回帰試験で2小節目だけの反復、反復中の400→200BPM変更による同小節頭からの再開、未選択時の全曲反復、停止後のcontext／lease解放、Project全体不変を確認。最初に実時間試験で再現し、修正後の試験で開始できることを確認した。

## Safari＋Mac mini本体の聴感報告と追加対策

利用者の確認では、USBオーディオインターフェース／モニタースピーカーではほぼ同期するが、Safari＋Mac mini本体スピーカーでは両画面とも音が遅れ、Editorでは再開時に停止前の音が少し鳴った。

Editorの通常停止だけを既存cancel経路へ変更。発音ノード・予約・タイマーは即座に止め、leaseを解放する。無音のcontextは既存の800ms待機で閉じる。その間の再生は同じcontextを再利用するため、旧contextを閉じて新しいcontextを開く切替を減らす。音源・OS設定・音量・音程は変更しない。全停止・入力の無効化・画面離脱では従来の完全cleanupを維持する。

Chrome／自動WebKitで停止直後はcontextがrunningだが音声所有権を持たず、直後の再開ではcontext数が増えず、再開しなければ閉じることを確認。さらに利用者がSafari＋Mac mini本体で「停止→1秒以上待つ→再生」を確認し、**残り音が出なくなった**と回答した。装置側のバッファが原因と断定する外部収録は行っていない。

追加の聴感確認で、利用者から「自動（0ms）で既にほぼ合う」と回答があった。これはSafari＋本体出力での利用者の確認結果であり、両画面を個別に外部収録した数値計測ではない。全出力へ一律の遅延を追加する変更はしていない。ブラウザの時計との一致だけで物理出音との一致を主張しない。Web Audioの出力timestamp／outputLatencyの定義は[W3C Web Audio仕様](https://www.w3.org/TR/webaudio/)を参照。

## 同期の計測方法

独立した新規ブラウザ保存領域と合成曲を使い、外部要求を遮断。実AudioContext・同梱音源・実ノードの発音予約を使用し、最後のGainだけ0にして検証時の出音を抑えた。製品の音量設定やOS出力設定は変更していない。

短時間の専用試験は、実際に予約した最初のメトロノーム拍の時刻を基準に、出力timestamp（非対応時はcurrentTimeとlatency）から絶対小節位置を計算し、DOM上の棒の座標と比較。0／+200／-200msを両画面・両エンジンで確認した。95％点の絶対差はChrome約0.5〜0.9ms、自動WebKit約3.7〜4.7ms。±200msの補正方向と小節位置が合うことを確認した。

これは出力時計と発音予約に対する描画の検証で、スピーカー・Bluetoothの物理出音や映像を外部収録した計測ではない。実Safariの手動操作・聴感の確認とも区別する。既存の波形回帰では、実音源をOfflineAudioContextで描画し、両再生計画とパート別音量を確認した。

30分試験はEditorで1小節反復、Viewerで12小節全曲反復を同時実行。BPM120・メトロノームON・カウントインOFF。1秒ごとに棒の数、拍に対する位置、未終了source数、累積発音数、JS heapの参考値を採取。拍位相の誤差は500ms周期内の差であり、単独では小節違いを排除できないため、上記の絶対小節位置試験で補う。

## 最終結果

- **実時間30分（1,800.429秒）の連続再生成功**。Editorは1小節反復、Viewerは12小節反復を同時実行。各1,800サンプル、棒の欠落／二重表示0、終了時のcontext解放を確認。発音予約総数45,044／39,909に対し、未終了sourceの最大37／15。保持するノード数が発音総数に従って累積する挙動なし。
- 拍に対する棒の差（1秒間隔計測）の絶対95％点はEditor **16.10ms**／Viewer **15.97ms**、最大 **19.11ms／18.71ms未満**。初め／終わりの5分の符号付き中央値はEditor -6.73→-10.42ms、Viewer -5.95→-10.97ms。数msの変化はあるが、全サンプルが約20ms内に収まった。描画フレーム内の計測タイミングによる揺れを含む。物理出音の誤差とは区別する。
- 30分試験の開始後に利用者から残り音の報告を受け、停止経路の追加対策を行った。そのため30分試験は連続再生の検証とし、対策後の停止／再開については別途Chrome／WebKitのUI試験と**実時間60秒の両画面再生・終了時解放**で確認。30分を追加対策後にやり直したとは主張しない。
- 全Node **2,352成功・失敗0・既存1skip**。親を含むブラウザ回帰は33＋34＋専用反復2＋同期2＋30分1＝**72成功**。追加対策後の関連18件と60秒試験も成功したが、重複ケースは72件へ加算していない。
- 対策後の関連18件には通し操作、練習テンポ、表示設定の試聴、停止、Project不変の境界も含む。72件のうち、Viewer側の未変更部分は先行成功結果を使用。
- 利用者のSafari＋Mac mini本体確認で、残り音が出なくなり、自動0msでほぼ同期するとの回答あり。USB／モニターで既に合っていた出力へ追加補正を入れていない。
- 詳細は `measurements.json`、短時間の絶対小節位置は `sync-chrome.json`／`sync-webkit.json`、ログ各ファイル。生の1秒データは `/private/tmp/score-playback-soak.json`（一時ファイル）。

最初の試験で旧2小節制限を実際に再現。新規単体試験の浮動小数点の完全一致前提は許容誤差へ修正。初期試験の失敗を最終成功へ混ぜて加算していない。

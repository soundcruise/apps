2026-11-16。作業ブランチ `codex/score-toolbar-ui`、基準 `bc9fea49`（push済み）。今回の差分はユーザー承認でローカルコミット。未push。既存のローカルサーバー `http://127.0.0.1:18874/` を再利用した。

## 修正

1. **JSON読み込みをキーボードで選べない**
   - Safariのアクセシビリティツリーでは、隠れたfile inputのlabelが「ファイル JSON読み込み」というテキストになり、操作ボタンとして認識されなかった。
   - 実行時のツールバー組み立てで通常のbuttonへ変更。既存のfile inputと読み込みトランザクションは維持。
   - ChromeのTab、WebKitのOption＋Tabで到達し、Enter/Spaceそれぞれがファイル選択を一度だけ開くこと、キャンセルが曲を変更しないことを確認。Safari実機でも修正後は「ボタン JSON読み込み」と認識された。

2. **選択後も「編集する小節を選択してください」が残る**
   - 未選択時に上書きしたtitleを戻していなかった。
   - 小節操作の本来の説明を保持し、選択・解除・再選択に合わせて切り替える。

3. **右側のフォーム編集で縦スクロール位置がずれる**
   - WebKitで右側編集欄を下端に置き、運指をクリックすると、scrollTopが764→731へずれた。横の指板位置と入力DOMは保持されていた。
   - コード図を更新する前にメロディカードも再構築していた。途中でカードの高さが縮む際にWebKitが親のスクロールを制限し、その後で位置を記録していた。
   - 既存のコード図の位置保持処理をメロディカード再構築より先に開始し、記録済みの縦・横位置を描画完了後に復元する。浮動・右側の両配置で確認。新たな待ち時間やスクロールアニメーションは追加していない。

## Safari実機で確認できた範囲と残件

通常のSafariプロファイルを使わず、新規プライベートウインドウに合成の「Safari実操作確認 — テスト用」をJSON読み込みして確認した。日本語歌詞の貼り付け・Enter確定・保存・再読み込み、未保存の表示、最新保存時の保存ボタン無効化、修正後のJSON読み込みボタン認識を確認した。テスト曲はプライベートウインドウ内に残している。

- **OSのかな変換は未確認。** ユーザーから「かな」キーで切り替えると教えてもらったが、自動操作ツールは `Hiragana` / `Kana` キーに `keyNotFound` を返した。貼り付けや合成compositionイベントを、OSの実変換確認とは扱わない。
- **SafariのOS印刷ダイアログは未確認。** 印刷ボタン操作時にツールがSafariの状態変更を検知し、操作を実行せず停止した。再取得後の再試行でも同じだったため、実機操作を終了した。プリンタへの出力は実行していない。
- 音源の聴感評価は今回の確認範囲に含めていない。

# 譜面クルーズ・譜面ビューワー 公開前の再確認

2026年11月21日。作業ブランチ `codex/score-toolbar-ui` の `da45ae6d` を使用。譜面の公開候補は `0.228.6-rc.1`。一時ディレクトリに配布物を生成し、ループバック配信・一時ブラウザープロファイル・合成譜面で検証した。Proの確認にはローカルのWorkerと使い捨てDBを使用した。

## P0対応結果（0.228.7-rc.1）

| 修正項目 | ローカルでの確認 |
|---|---|
| 通常のStudio配布手順 | `node apps/cruise-studio/scripts/package-port-pc.mjs --out <新しい出力先>` で、Standard・Proの譜面エディター、取扱説明書、ポートの入口、独立ビューワー、音源・オフライン資産を含む765ファイルを生成した。ビルド時に同梱モジュールのローカル参照とオフライン資産を検査する。 |
| FirefoxのPro入場 | Firefoxが端末公開鍵に付ける `alg: ES256` をクライアント側で送信形式に合わせた。既存の端末鍵もそのまま使用する。ローカルの正規の入場処理、保存後の再入場、既存の鍵を再使用する更新試験が通った。 |

通常の配布物を `node apps/cruise-studio/scripts/serve-score-candidate.mjs <出力先>` でループバック配信した。Chrome・WebKit・Firefoxの各Standard・Proで曲を作成し、保存後の再読込、ビューワー書き出し、元譜面との一致、再生・停止を確認した。Chromeのファイル保存にはテスト用ファイルハンドルを使用。WebKitとFirefoxはブラウザー内保存を確認した。独立ビューワーでは保存済み譜面をサーバー停止後に再度開いて再生できた。

通常の配布物には既存のニュース・アカウント設定を同梱する。ローカル試験ではニュース応答とProの認証先を隔離した。iPhone実機の確認は保留。

## 修正前の判定（0.228.6-rc.1）

| 優先度 | 残課題と確認結果 | 完了条件 |
|---|---|---|
| P0 | **公開に使う配布手順。** 譜面専用候補には必要なモジュールがそろう。一方、通常のStudio配布物では、同梱された譜面モジュールから相対参照するファイルが10個不足。`score-settings.mjs` を読み込むと `page-help.mjs` が見つからず失敗した。通常入口のCSSキャッシュ番号も通常版の管理値と食い違う。 | 正式配布に使う入口・ファイル一覧・キャッシュ番号をそろえ、配信予定の成果物そのもので、公開対象の各版について編集・保存・書き出し・ポートからの再生を通す。既存の通常版公開範囲を変える判断は別途行う。 |
| P0（FirefoxのPro版） | **Proに入れない。** PCのPlaywright Firefoxで通常版は作成からオフライン再生まで通った。Proはローカルの正規の入場手順で HTTP 400 `invalid_device_key` を再現。Firefoxが正規に生成した端末公開鍵には `alg` フィールドが加わり、現行の受理条件から外れる。Chrome・WebKitではこの追加フィールドがなく、同じPro試験を通過。 | Firefoxの公開鍵形式に対応し、既存の端末確認と不正な鍵の拒否を保った上で、Firefoxでの新規入場・再入場・譜面の保存と再生をローカルで再検証する。共有Pro入口として扱う。 |
| P1（実機受入・iPhoneは保留） | **モバイル版ビューワーのOS・機器依存動作。** 以前のiPhoneでの横向き操作と、今回の縦横のブラウザー試験は確認済み。現候補でのSafari完全終了後のオフライン復帰、自動ロック防止、Bluetooth出力での音と再生棒の体感差は保留。 | iPhoneが使える時にまとめて確認する。カメラ周辺の余白、メニューの背面への誤タップ、BPMの複数桁入力、PDFの取込・保存・ページ送りも実タッチで確認する。iPad・Android実機の受入も別途。PC用エディターのスマホ最適化は対象外。 |
| P2 | **共通UIと保存容量の回帰試験。** 共通UIでは両エンジンとも、変更破棄の確認を扱わないテストと、再生棒に旧色を期待するテストが失敗した。保存容量の既存ブラウザー試験7ケースも、旧保存操作・固定版番号・下書き導入前の書き込み回数を想定。 | リポジトリ上のテストを現仕様に更新する。確認を取り消した場合の変更保持、破棄した場合の復元、8 MiB境界を越えた場合の元譜面保持を引き続き検査する。 |
| P2（Studio共通・同期の検証） | 通常のNode試験でスキップされる同期復旧E2Eも、専用の一時環境と固定版Workerで別途起動した。通常起動時に書き込みを行わない検査は通ったが、最初の合成曲を送信待ちに登録する段階でクライアントが `project-invalid` を返した。 | テストが作成する曲と通常Studio入口のスキーマ設定を照合し、隔離環境で復旧試験を再実行する。今回成功したローカルファイル保存とは別の経路。 |
| P3 | **説明とキーボード操作。** 譜面モジュールREADMEには「表示設定は曲JSONに含めない」との記載が残るが、現行の書き出しは譜面の表示設定を保持する。上部ツールの任意順への並べ替えはポインターのドラッグ操作に限られる。 | 端末設定と曲に書き出す設定を区別してREADMEを直す。ツール順をキーボードでも変更できる操作を追加する。 |

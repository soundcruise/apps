# Official Rhythm selection and adoption — R6 development candidate

Studio candidate 0.45.0 / schemaVersion2. Production remains Studio0.43.1 / Rhythm1.20.0. R3 candidate1.21.0 is not merged or published here. This topic alone is not a production integration/release. R3/R4/R5/P2 source contracts and saved musical authority are unchanged.

## Structure UI and targets

The collapsible Rhythm panel sits in Structure's existing editor drawer beside the basic stroke controls. It uses the existing Structure document and selection; there is no new workspace, Session, Undo stack or Save button. The user selects **曲全体の基本リズム** or **選択した小節のリズム**. Current formal Structure selection is single-bar: the stable bar ID is resolved from `getSelectionSnapshot`, and the number is a display label only. Empty, deleted or ambiguous selection refuses; R6 does not fabricate a multiple-selection UI. R5's multi-bar Service remains unchanged and independently tested.

The formal owner catalog supplies names, IDs, revisions and stage order: five eighth-grid and four sixteenth-grid entries. There is no second musical table. The read-only preview uses the R5 handle's verified R4 projection, with attack/down/up, rest and sustain shown separately; small screens wrap sixteen cells over two eight-cell rows. Beat boundaries and accessible cell labels remain explicit. No air/dead/stop/accent/pitch/strings/voicing, Audio or complete guitar TAB is invented. `performanceReady` and `completeScore` remain false.

Adopt invokes existing `prepare`/`apply`; reuse invokes `prepareReuse`/`apply`; **基本リズムに戻す** invokes `prepareClear`/`apply` for the selected bar override only. That differs from P2's blank legacy custom-basic input. Basic adoption keeps every bar override; bar adoption keeps basic/other bindings; clear never deletes materials. Same-content/same-target is the existing R5 no-op. One actual change is one existing Undo entry. Only Studio's existing explicit Save persists. Storage failures keep the adopted dirty draft/history. R6 never writes canonical material/reference fields itself.

A small `refreshRhythmView` bridge exposes existing Structure redraw for an explicit successful R6 edit. It runs after that action in a deferred callback which rechecks the current Session/workspace. It updates the legacy editor's native unsupported/disabled state and score without adding a Session notification render to every melody command. Ordinary melody/song/Chord/Print/Pre-DTM/JSON paths retain their existing owners; R5 native unsupported outputs remain explicit.

## Verified owner acquisition and unpublished boundary

Nothing queries/imports the Rhythm owner (or instantiates the R4 adapter/R5 Service) on normal Studio boot. The panel imports its Studio controller/loader only on explicit opening. Opening reads saved adopted data first; official acquisition is separately lazy and retryable. An unavailable owner never becomes a fake catalog and does not break Studio boot. Saved names, selected Material IDs, basic/inherited/override relationships and read-only native previews use the existing saved data/Offline reader. Saved native and legacy materials can be reused without owner availability; native data is never approximated as old slots.

`owner-loader.mjs` pins actual R3 Git commit/tree/module SHA256 and the independently checked version-source receipt. It requests only the owner ESM asset on the same host, with credentials omitted and redirects rejected. It bounds the body, hashes the returned bytes with Web Crypto SHA256, and **executes that same verified buffer** via an ephemeral JavaScript Blob URL. It never validates one fetch then imports a separately fetched URL. The Blob URL is revoked after module evaluation. R3's pinned module has no imports/global/DOM/Storage/Audio/network initialization. No copied owner product file is committed to Studio. The fixed receipt describes that historical source; it is neither an entitlement nor a claim that Production Rhythm has changed versions.

Only after verification does the loader bind the actual exports into the unchanged R4 facade. The catalog is validated by R4. Pin mismatch, missing module, invalid catalog or fetch error rejects new acquisition; saved-data browsing/reuse survives. Successful immutable owner display data can be shared across panel reopen; Project adoption handles never are. The dependency injection points are explicit trusted test/host constructor dependencies, not a product fixture global or arbitrary URL setting.

Tests serve actual fixed R3 bytes at the owner asset URL through an isolated Browser route. That route, fixtures and credentials are not product code. The ordinary unavailable-owner case is separate and records its intentional failure response; it is not mixed with ordinary boot/404/console success. Before any production integration: integrate the separately approved R3 owner, inspect its asset placement/import-free body/CSP Blob policy, retain source byte identity, update the Rhythm production metadata/cache to its actually released version, then re-run all integration/release gates. No main/Pages release is authorized here.

## Candidate lifetime, rendering and No-write

The controller keeps only an R5-issued handle plus an exact UI frame (Session object/version, document/workspace generation, base raw revision, target and current stable selection). Selection or target changes, Session notifications, project/workspace changes, IME, modal and external-storage changes invalidate the handle. R5 independently rechecks actual identity/history epoch/raw revision/capacity at apply; an invalid UI frame is not submitted. Failed handles are not reused. Deferred paints recheck eligibility. IME completion schedules one eligibility refresh after the existing keyboard guard's task boundary; it does not change that guard. A closed/hidden panel cannot apply by synthetic click. Listeners, RAF and that owned timer are disposed; Escape stays local and restores the toggle, preserving Shell modal/IME ownership.

Session/document/selection subscriptions are attached only while the panel is open, and detached on close/dispose. Closed-panel code has no Session-notification work. Open-panel notifications only invalidate and schedule a frame, without owner calls, prepare, full Project cloning, or nine-material validation. Catalog acquisition happens once per verified loader; previews are prepared only by explicit selection. Saved preview reuse is a bounded single display value compared against the complete material JSON; it never bypasses R5 validation, raw-revision checks or authorization. Rendering is not a second saved authority.

List/read/preview/prepare are write0; apply/clear/Undo/Redo use the existing memory Session only; explicit Save alone uses Repository. Test ledgers distinguish setup, settings and explicit project-selection preference writes from the write0 rhythm phases, and retain writes across reload. Shared write stays OFF and PortDataHost.canWrite=false. No Pro/Account/Sync/Authority/Worker/Daybreak operation is introduced.

## R6 independent-review P2: inert / hidden interaction boundary

The existing unreleased0.45.0/schema2 candidate receives this limited compatibility fix; Production versions/cache and the owner release remain separate. DOM eligibility is owned only by the panel: open/not disposed, connected target inside the panel, correct workspace, no hidden/inert self or ancestor, CSS visibility/display/content-visibility and actual checkVisibility, Modal and IME. aria-hidden alone is not inert. The same predicate drives button display, preparation, immediate adopt/clear handlers and the context.blocked delivered to the unchanged controller/R5 Service for the actual action target. Disabled controls are presentation, not the enforcement boundary. Refused synthetic events invalidate the candidate without submitting apply/clear or changing Project/history/repository.

While open, a bounded observer watches attributes on the panel, body/actions and their ancestor chain, with direct-child changes only on ancestors (no document subtree). Mutating handlers first drain pending observer records, so same-task inert/unblock cannot revive an old handle before the callback. It invalidates on inert/hidden/style/class/details changes, including transitions back before the callback, and is disconnected on close/dispose. Own disabled/aria/preview subtree updates are not observed. Reopening or removing inert requires fresh preparation after a non-interaction interval; normal adopt/reuse/clear remains available. Closed-panel Session subscriptions and observer work remain zero. Saved-data, revision/history/capacity checks, owner verification, single Undo and explicit Save are unchanged.

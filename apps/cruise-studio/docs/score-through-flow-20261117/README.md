## 通し操作

Chromeと自動WebKitの隔離contextに合成譜面を読み込み、DOM上のボタン／入力欄で以下を実施した。元のユーザー保存領域は操作していない。

1. 2小節編集の2小節目へ歌詞を入力し、行の音価を変更して確定。Undo／Redo後の内容を確認。
2. 2小節目の後半のコードをDmへ変更し、編集画面を閉じて保存。保存済みボタンの無効化と再読み込み後のProject全体の一致を確認。
3. 表示設定でフォーム一覧を有効化。新規フォルダを作って書き出し、同名上書きでフォルダが維持されることを確認。
4. 別名入力をキャンセルした後、改めて別名で書き出してViewerへ移動。
5. 2小節を選択し、反復・ミュートで再生／一時停止。選択2小節の表示と原本hashの不変を確認。
6. ライブラリの元のフォルダから元ファイルを開く。別名ファイルと異なるentry ID／hash、元Projectと音楽データ全体が一致することを確認。
7. 再読み込み後に同じ原本hashを復元し、編集画面へ戻って保存済みProject全体が一致することを確認。

既存試験では、拍ロック優先／全・2分を含む行の音価切替、詳細表示の保存／取消、音設定、全画面・狭幅、履歴の移動／プレビュー／取消／二段階確定／後続履歴破棄／古い確認の拒否も確認。

ローカル候補 **0.139.0-dev.1**。HEAD `7f69b433`、`codex/score-toolbar-ui`。先行0.132〜0.138の未コミット差分を保持。正式製品版0.88.1、本番配信・公開HTML・実Account/Sync・他アプリは変更していない。コミット・pushなし。

## 画面で変わること

- 再生設定の常設説明を外し、見出し横の「？」にまとめた。音量やガイドの動作、保存先をここから確認する。
- 上部カードの「○小節目から」と通常の操作結果を表示しない。再生ボタンの説明と支援技術向け通知は保持し、入力・保存エラーは引き続き表示する。
- 控えめな「履歴」ボタンから、現在位置周辺の保持履歴を最大20変更程度表示する。選んだ時点へ戻せ、残っている未来の状態はやり直せる。保存基準は変えないので、保存内容と同じ状態なら保存ボタンはグレーになる。履歴は既存Editing Session内だけで保持し、再読み込み後へは保存しない。
- 保存は未保存の内容があるときだけ有効。「曲メニュー → 名前をつけて保存」で、元の曲を残して現在の内容を別の曲として保存する。元の未保存Sessionも保持する。JSONダウンロードとは別の操作。
- グリッド線のチェックと分割設定は「表示設定」へ移動。見本へ反映し、保存／キャンセル、表示プリセット、再読込に対応する。
- 拡大フォームは閲覧状態で開き、「編集」を押したカードだけで編集する。押弦位置をクリックすると、既存のコード編集と同じ順序で指・注意表示・ミュートへ進む。開放弦は直接ミュートへ進む。ミュートの×を押すと開放弦へ戻す。「譜面に反映」で対象コードへまとめて適用。キャンセル・外側クリック・Escapeでは未反映の変更を破棄し、次のフォームは再び閲覧状態で開く。
- 通常の編集カードから白黒フォームを開く場合も同じ拡大カードを使う。鳴らす弦の指定を紙面・拡大・白黒／カラー編集に共通適用し、ミュートした弦の黒丸が残る不一致を修正した。

## 保存・履歴の契約

`Editing Session.restoreHistory(cursor,ticket)`は、Session ID・履歴epoch・snapshotVersion・現在内容を確認したうえで、既存の保存済み履歴内容を1回だけ検証・公開する。保存済みbase、revision、時刻などのmetadataを巻き戻さない。途中の状態を順々に公開せず、Undo/Redoのカーソルと未来の履歴を保持する。入力中・保存中・古い履歴・不正な位置は変更せず拒否。既存Undo/Redoの保存契約は維持した。

別名保存は新しいprojectIdを発行し、元のProjectを変更せず複製する。内部のコード／素材参照は維持し、元から確認済みで有効なフォームのbasisKeyだけを新しいProject IDに合わせる。既存RepositoryのWeb Lock・権限確認・revision CAS・原子的なProject/一覧保存を通す。新規保存に成功してから新しい曲へ移り、失敗・キャンセル・入力変更・古い対象では原本とdraftを保持する。日本語変換のEnterで意図せず別名保存しないように保護した。

表示設定の新しい`timingGrid`/`gridResolution`はブラウザ内の設定。未指定はnullで、元Projectの表示値をそのまま使う。明示変更後は他の表示設定と同様に保存・キャンセルする。既存の曲データを移行したり、notationの値を書き換えたりしない。

フォームの共通`form-cycle.mjs`を、元アプリの実際のstored-note cycleと照合。指変更の順序を揃え、描画では既存playedStringsを共通に参照する。既存のplayedStringsだけでミュートされた素材でも黒丸を出さないことを検証。閉じたカードに編集状態や操作が残らず、別コードへ変更が漏れない。通常のSession/adopt/immutable素材とUndo/Save/JSONは維持する。

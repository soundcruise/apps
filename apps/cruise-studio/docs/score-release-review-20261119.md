# 譜面クルーズ・譜面ビューワー 公開前の確認事項

2026年11月19日、開発版 0.195.1-dev.1。合成譜面、一時ブラウザプロファイル、ローカルの配布物を使って確認した。

| 優先度 | 確認したこと | 公開前に決めること・合格条件 |
|---|---|---|
| 公開の前提 | 現行のStandard・Pro入口で譜面作成は無効。公開用パッケージを一時ディレクトリに生成すると、212ファイルの中に譜面再生モジュールと独立ビューワーの入口が含まれない。開発用ビューワーの起動先は localhost に限定され、同期はテスト用。 | 公開する版と入口を決め、実際に配るファイルだけをローカル配信して、作成→保存→書き出し→ビューワー再生を通す。 |
| 高・保存先 | Chromeで「名前をつけて保存」を実行すると、別の曲をブラウザ内に作成する。保存先選択の呼び出しは0回。複製先は保存済みとなり「保存」は無効。WebKitで通常の「保存」を押すと、ファイル選択APIがなく、ブラウザ内に保存して「保存しました（曲名）」と表示する。 | 曲を複製する操作と、PCに別名ファイルを作る操作の名称・保存先を揃える。ブラウザ内に保存した場合は保存場所とファイル書き出しの入口が分かる表示にする。 |
| 高・演奏内容 | 押さえ方が未登録のコードには、エディターでコード名から参考和音を鳴らす経路がある。ビューワーのファイルは未登録の状態も受け付ける。その場合に警告が付き、ギターの発音が0件、メロディの発音が残ることを回帰テストで確認。通常の書き出し完了表示からは、どの小節が該当するか分からない。 | 未登録フォームを含む譜面で、書き出し前に該当小節を知らせるか、演奏用ファイルに押さえ方を確定して含めるかを決める。 |
| 操作性 | ツールの追加・解除、既定順への復帰、設定の開閉はキーボードで操作できる。任意の位置への並べ替えはポインターのドラッグに割り当てている。 | キーボードだけで並べ替えられる操作を検討する。 |
| 実機での受入 | 以前の実機記録にはiPhone縦向きの動作確認がある。今回のブラウザ回帰はMac上のChrome・WebKitで実施した。 | 現候補でiPhone横向き、iPad、画面消灯防止、Safari終了後のオフライン再起動、ビューワー内でのPDF保存・ページ送り、Bluetooth使用時の音と再生棒を実機確認する。 |

通常保存のファイル選択に対応したChromeでは、通しテストの保存先を隔離プロファイル内のファイルに指定し、書き込んだ小節・演奏データと編集中の譜面の一致を確認できるようにした。OSの保存ダイアログでの手動操作は別途受入対象となる。

ローカル検証の結果は、StudioのNodeテスト2,382件成功、専用環境が必要な統合テスト1件スキップ。Chrome・WebKitの6スイート（ツールバー、編集から演奏までの通し操作、再生・試聴、共通UI、モバイル表示、PDF）は親テストを含む90件すべて成功。

確認に使用した主な資料は [公開版と開発版の分離方針](public-release-0880/DEVELOPMENT-LINES.md)、[ビューワーの演奏テスト](../tests/viewer-contract.test.mjs)、[過去のスマホ実機記録](score-operated-soak-mobile-20261117/README.md)。

# 譜面クルーズ・譜面ビューワー 公開前の確認事項

2026年11月19日、開発版 0.195.1-dev.1。合成譜面、一時ブラウザプロファイル、ローカルの配布物を使って確認した。

| 優先度 | 確認したこと | 公開前に決めること・合格条件 |
|---|---|---|
| 公開の前提 | 現行のStandard・Pro入口で譜面作成は無効。公開用パッケージを一時ディレクトリに生成すると、212ファイルの中に譜面再生モジュールと独立ビューワーの入口が含まれない。開発用ビューワーの起動先は localhost に限定され、同期はテスト用。 | 公開する版と入口を決め、実際に配るファイルだけをローカル配信して、作成→保存→書き出し→ビューワー再生を通す。 |
| 対応済み・保存先 | 開発版0.196.0で、保存先を選べる環境の「名前をつけて保存」と、ブラウザ内で別の曲を作る「曲を複製」を分けた。ブラウザ内に保存した場合は、その旨とJSON書き出しボタンを表示する。 | 開発版0.196.0の実Chromeで、別名保存後の再読み込み・上書きを確認済み。 |
| 対応済み・伴奏 | ビューワー0.19.0は、押さえ方が未登録のコードを譜面クルーズと同じコード名・構成音の規則で再生する。既存の書き出しファイルもそのまま開ける。 | Chrome・WebKitで、元譜面から書き出したファイルを別プロファイルの独立ビューワーに読み込み、Cmaj7/E のダウン・アップで各5音のギター音源と再生レートが一致することを確認した。書き出し前後と読込後の譜面データも一致した。 |
| 操作性 | ツールの追加・解除、既定順への復帰、設定の開閉はキーボードで操作できる。任意の位置への並べ替えはポインターのドラッグに割り当てている。 | キーボードだけで並べ替えられる操作を検討する。 |

通常保存のファイル選択に対応したChromeでは、通しテストの保存先を隔離プロファイル内のファイルに指定し、書き込んだ小節・演奏データと編集中の譜面の一致を確認できるようにした。

macOS 26.6.2、Google Chrome 157.0.8103.80、開発版0.196.0-dev.1のローカル実機確認では、標準の保存ダイアログで元ファイルを作り、「名前をつけて保存」で別フォルダと別ファイル名を指定した。ページ再読み込み後にBPMを100から127に変えて「保存」を押し、Chromeの書き込み権限で「今回のみ許可」を選択。別名ファイルだけがBPM 127に更新され、元ファイルはBPM 100、SHA-256と更新時刻も保存前と一致した。

保存まわりの変更（0.196.0-dev.1）のローカル回帰は、Chrome・WebKitのブラウザテスト58件成功（親テストを含む）。StudioのNodeテストは2,382件成功、専用環境が必要な1件スキップ。

前回の公開前確認（0.195.1-dev.1）では、StudioのNodeテスト2,382件成功、専用環境が必要な統合テスト1件スキップ。Chrome・WebKitの6スイート（ツールバー、編集から演奏までの通し操作、再生・試聴、共通UI、モバイル表示、PDF）は親テストを含む90件すべて成功。

確認に使用した主な資料は [公開版と開発版の分離方針](public-release-0880/DEVELOPMENT-LINES.md)、[ビューワーの演奏テスト](../tests/viewer-contract.test.mjs)、[過去のスマホ実機記録](score-operated-soak-mobile-20261117/README.md)。

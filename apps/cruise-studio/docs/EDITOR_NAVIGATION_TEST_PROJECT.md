# 編集ナビゲーションと操作テスト曲 — 0.118.0-dev.1

## 編集時の移動

- 小節選択の変更に伴う紙面の自動スクロールを廃止。セル末尾のEnter/→、小節移動ボタン、2小節表示内の移動も紙面位置を変えない。入力欄へのフォーカスはpreventScrollを維持。
- 全曲再生の追従・手動スクロール優先は別処理のまま維持。
- 編集カードの余白・行名、またはEscapeでセル編集を解除したカード上から上下左右で小節選択。カードは開いたまま、移動後もカード全体へフォーカス。右窓でも同じ。
- 上下は紙面の行と列を基準にし、灰色の空き枠を飛ばす。左右は隣の実小節。セル・音・ストローク・ボタン・文字選択のキーはそれぞれの操作が優先。IME、未確定/不正入力、保存中、競合、モーダル等の既存ガードは維持。
- 紙面の左右の余白（紙の余白・外側）をクリックすると、通常の閉じる操作と同様に編集を終了。カードやボタン、コード拡大、設定ダイアログ等は巻き込まない。不正入力は保持して閉じない。

## テストProject

`node apps/cruise-studio/scripts/create-ui-test-project.mjs /absolute/new-file.json`

新しい出力ファイルだけに書き出す。既存ファイルを上書きせず、ブラウザ保存領域・実アカウント・Cloudへ接続しない。

「編集操作テスト — 海辺の散歩」は、書き下ろしの4セクション/12小節。標準6弦・22F・カポ0・C・4/4・BPM100。24コードすべてに既存おすすめロジックのフォームを登録。歌詞、C3/C4/C5、1マス内の複数音、伸ばし、アップ/ダウン/ミュート、明示的に空欄のストローク小節を含む。実ユーザーの曲・本棚・資格情報は含めない。音価は合成曲の明示値として確定し、既存曲の未確定音価を変更しない。

空欄ストローク小節を含む行で歌詞・ドレミが上に詰まる表示不具合も修正。表示ON中は空のストローク行を保ち、隣の小節との段を揃える。素材や再生用イベントを追加しない。

Safariの18874で通常のJSON読み込みと保存を実行。元の「無題のプロジェクト 1」は先に保存して保持し、テスト曲を別Projectで追加。フォーム表示ONで保存済み。紙面の行指定や文字設定はユーザーの既存設定を保持。新しい修正は18874の再読込みで反映される。

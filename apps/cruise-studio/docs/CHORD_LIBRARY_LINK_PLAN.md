# コード本棚連携：進捗と次の開発単位

2026-11-12。利用者の希望「本棚との連携を忘れないうちに進めたい」を記録。

## 0.107で追加した直接選択

利用者が承認した「別タブ＋読取り専用ブックマーク」を実装。18874からPro単体を開き、通常認証後に本棚で補助を起動する。ネイティブの本棚カードを選んで名前／固定フォームを元のマスへ返す。元本棚の保存契約は変更せず、個別カードの閲覧ハンドラーより前で選択を受け、保存正規化や書戻しを呼ばない。

送信元origin＋開いたタブ＋使い捨て識別子を照合し、入力先の変更・期限切れで破棄する。ローカルのCSP・API遮断を維持する。JSONの予備経路を残す。実Pro本棚／実Safariは利用者確認待ち（HOLD）。[操作手順](CHORD_NAME_TRANSFER_GUIDE.md)。以下は以前の経緯。

## 今回完了した範囲

0.103.0-dev.1で、コード名だけのJSON書出し補助と取込みを実装した。[操作手順](CHORD_NAME_TRANSFER_GUIDE.md)。元の本棚・認証・公開入口は変更せず、通常認証後のPro単体ページで利用者が起動する読取り専用ブックマークを使う。合成本棚での実ダウンロードから譜面入力までを検証。実本棚／実Safariでの利用はHOLD。

元のExplore UI／CSS／指板レンダラーをローカル専用の隔離DOMへ組み込んだ。設定はメモリ内だけに保持し、コードクルーズ本体のlocalStorageへ接続しない。今回の転送は専用v1のformat／version／sourceAppと、選択フォルダのID・名前、選択コードのID・folderId・名前だけ。フォーム・builder spec・メモ・認証・Sync情報は含めない。

取込み一覧はSessionごとの一時カタログで、一覧表示・選択だけではProjectや履歴を変えない。明示入力だけを既存のSession／Undo／保存へ渡す。再読込で一覧は消え、入力して保存したコードは通常のProjectに残る。元本棚への書戻しや自動同期は行わない。

## 次に判断が必要な範囲

0.106.0-dev.1で3点の設計方針が承認され、自動フォーム・手動固定・名前とフォームのJSON取込みをローカル実装した。[現在の設計と保護条件](CHORD_FORM_COMPATIBILITY_PLAN.md)と[操作手順](CHORD_NAME_TRANSFER_GUIDE.md)を参照。以下は過去候補の判断記録であり、現時点の未実装一覧ではない。ベース／テンション個別指定や未確定弦など、単一の6弦フォームへ安全に表せない本棚レコードは推測して変換しない。

0.105.0-dev.1で、基本ビューを「選択中の1フォーム＋ダイアトニック横並び」へ変更。コード名は一覧選択で直接入力する。現在のUI／判断事項は[互換設計案](CHORD_FORM_COMPATIBILITY_PLAN.md)を参照。以下の0.104の選択記録は経緯として保持する。

0.104.0-dev.1では、利用者が「小節内の全コードを拍位置へ配置」「標準6弦・22Fを初期条件」「互換設計を先に確認」を選択した。表示のみを先に実装し、[フォーム保存の互換設計案](CHORD_FORM_COMPATIBILITY_PLAN.md)を提示する。自動登録・手動編集・本棚フォーム転送の保存拡張は確認待ち。

保存済みフォーム・任意フォーム編集の採用は未実装。現行schema2のフォームは `origin=owner-recommendation`、`adapterVersion=2`、`externalMaterialId=null` に限定される。本棚の保存フォームや手動編集フォームを、おすすめ由来と偽って採用しない。

進める場合は、外部スナップショット／手動編集の由来、所有ID、確認条件、使用弦、カポ／チューニング、未確定弦の意味を先に定義し、保存契約の拡張を利用者に判断してもらう。将来フォーム付きの転送形式が必要になっても、今回のコード名専用v1へ項目を黙って追加しない。

本棚カタログ自体を再読込後も残す場合は、保存先と更新／削除契約を別途決める。常時接続やCloud／Syncは今回のローカル検証の対象にしない。将来本番で統合する場合も、所有モジュールに明示的な読出し契約を用意し、別アプリのlocalStorageをStudioが直接読む構成にしない。

## 継続する受入条件

- 合成した小さい本棚JSONのみで試験し、実ユーザー本棚を試験データにしない。
- 一覧表示だけではProject・未保存draft・履歴を変更せず、選択した拍への明示入力だけをUndo対象にする。
- 重複ID、同名コード、巨大／不正ファイル、未対応版、古い選択／別Projectへの遅延適用を扱い、既存内容を保持する。
- Schema／CAS／フォーム素材不変・保存失敗・競合・Undo／Redo・保存再読込・JSON再出力・Chrome／WebKit・外部通信0件を維持する。

# コード本棚連携：次の開発単位

2026-11-12。利用者の希望「本棚との連携は忘れないうちに進めたい」を保留課題として記録。

現状：コードクルーズの本棚は、同アプリのoriginにある `chordCruise.*` を所有する。18874は独立したローカル検証originで、本番保存領域を直接参照しない。今回追加したコード入力パネルは、本棚・Chord UI/storage・Account・Syncを読み込まない。

## 推奨する順番

1. **コード名の選択を先行する。** コードクルーズ側に、利用者が選んだフォルダ／コードだけをJSONに書き出す入口を追加する。譜面クルーズでは利用者がそのファイルを選び、フォルダ／コード一覧を表示し、選択したコード名だけを現在の拍の既存コード入力へ渡す。この段階はschema2を変更せず、既存のSession、Undo/Redo、明示保存を使える。ファイル交換なのでクラウドや別originへの通信も不要。
2. **本棚の押さえ方の利用を別途設計する。** 現行schema2のフォームは `origin=owner-recommendation`、`adapterVersion=2`、`externalMaterialId=null` に限定される。本棚の保存フォームや手動編集フォームを、おすすめ由来と偽って採用しない。外部スナップショット／手動編集の由来、所有ID、確認条件、使用弦、カポ／チューニング、未確定弦の意味を定義してから、保存契約の拡張を利用者に判断してもらう。
3. 常時接続やCloud／Syncはこのローカル検証の対象にしない。将来本番で統合する場合も、所有モジュールに明示的な読出し契約を用意し、別アプリのlocalStorageをStudioが直接読む構成にしない。

## JSON受渡し案

版付きの専用envelopeに、選択フォルダ、安定した元コードID、表示名、構成音／builder spec、保存フォームsnapshot、元アプリ／版の由来を入れる。Syncバックアップや資格情報を渡さない。書出し側では既存データを書き換えない。取込み側はファイル容量・件数・文字列長・配列長・数値／弦／フレット範囲・スキーマ版を検証し、不明項目を実行・自動移行しない。

最初の取込みは一時カタログとして画面内で保持する案を推奨する。再読込後も本棚カタログを残す必要がある場合は、その保存先と更新／削除契約を別途決める。選んでProjectに入力したコードは既存の保存経路だけで保全する。元本棚への書戻しや自動同期はしない。

## 受入条件

- 合成した小さい本棚JSONのみで試験し、本番・実ユーザー本棚を試験データにしない。
- 取込み／一覧表示だけではProject・未保存draft・履歴を変更しない。選択した拍への明示入力だけを1回のUndo対象にする。
- 重複ID、同名コード、巨大／不正ファイル、未対応版、非標準チューニング、古い選択／別Projectへの遅延適用を拒否し、既存内容を保持する。
- Schema/CAS/フォーム素材不変・保存失敗・競合・Undo/Redo・保存再読込・JSON再出力・Chrome／WebKit・外部通信0件を確認する。

この文書は次工程の提案であり、本棚の取込みや保存契約の拡張を実装済みとはしない。

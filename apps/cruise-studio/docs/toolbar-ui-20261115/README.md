# 譜面クルーズ 上部カードの整理 — 0.128.0-dev.1

基準コミット `6a95c4b8`。ユーザー承認の「小節選択時に小節操作を表示」案をローカルに実装。作業ブランチ `codex/score-toolbar-ui`、正式版は0.88.1のまま。公開HTML・本番配信・認証・実Account/Sync・既存アプリ・共有CSSは変更していない。コミット・pushは別指示まで実施しない。

## 画面の変更

- 常設は曲選択、曲メニュー、右上の表示設定、再生、保存、Undo/Redo、表示項目、ズーム。
- 曲メニューには新規作成、曲情報・セクション、移調、コードフォーム確認、印刷、JSON入出力を収める。メロディ譜への切り替えと五線更新は表示項目メニューに収める。
- 小節を選択すると、対象小節番号、編集、小節追加、複製、コピー、貼り付けを表示。前後移動と削除は「小節操作」内。未選択では操作列そのものを消す。複数選択時の既存の適格性・コピー制限は維持する。
- 表示項目メニューのチェックは、譜面の表示順を維持して連続操作できる。外側クリック・Escape・別メニューの開始で閉じる。Escapeでは開いたメニューの見出しへフォーカスを戻す。
- 曲情報カードは閉じている間は重複表示しない。「曲情報・セクションを編集」から既存カードを開き、曲名へフォーカスする。新規曲で既存のカードが開く動きは維持。
- 「戻る／ホーム」と上部カードが重ならないよう、ローカルの譜面画面だけsticky位置を調整する。

既存のボタンと入力要素を移動し、IDとイベント処理を保持している。新しい保存・履歴・音声処理やProjectの複製実装は作らない。表示設定の保存先や、従来の表示チェックがProjectまたはブラウザ設定に反映される契約も変更していない。

## メニューと編集中カード

浮動編集カードがメニューを隠さないよう、対応ブラウザではメニュー本体だけをnative popoverで前面に出す。上部カード全体を前面には出さず、編集中の鍵盤や入力を塞がない。非対応時は開いたメニューの間だけ既存の重なり順で前面化する。外側クリックはcaptureで処理し、編集カードがクリック伝播を止めても閉じる。Spaceと矢印はメニュー・チェック・selectが所有し、譜面再生／小節移動と競合しない。印刷開始・印刷mediaへの切り替え・画面離脱でもメニューを閉じ、print CSSでも除外する。

既存の入力不正、IME、未確定、保存中、競合などのガードは各元コマンドのまま維持。出力ガードを迂回する処理は追加しない。メニュー開閉や表示だけではProject/Undoを変更しない。

## 確認方法

既存のローカル専用入口 `http://127.0.0.1:18874/` を使う。ユーザーのブラウザ保存領域や実アカウントは使わず、隔離Chrome/WebKitと合成Projectで確認した。

1. 曲を開き、上部カードが通常2段であること、小節選択で操作列が出ることを確認。
2. 編集、コピー／貼り付け、追加、複製、削除を行い、Undoで復元できることを確認。
3. 表示項目を続けて変更し、メニューを開いたまま反映できることを確認。
4. メニューを開いた状態から編集カードを操作、Escape、外側クリック、印刷、画面離脱を確認。
5. 曲情報の編集、保存、再読込、JSON入出力、既存の音声停止・再生を確認。
6. 幅320/390/768/1440pxでメニュー・主要ボタンが画面内に収まり、印刷には出ないことを確認。

既存ブラウザ試験は、移動した要素に対してメニューの見出しを実際に押してから操作する共通helperへ更新。強制クリックや非表示のコマンドの直接実行で置き換えていない。

最終検証: Chromeの譜面回帰122件成功、WebKitの対象回帰19件成功。新メニューと実ローカル入口16件、実Web Audio・入力不正時のJSON/印刷ガード・128小節の表示設定5件が成功（親テストを含む）。全Nodeは2,126成功・既存と同名の39失敗・5スキップ、新規失敗なし。

検証集計は [verification.json](verification.json)。変更前からのNode失敗39件は失敗名を比較し、追加がないことを確認する。WebKit試験はSafari実機試験とは区別する。Safari実機・実アカウント本棚・OS印刷ダイアログは今回未確認。
